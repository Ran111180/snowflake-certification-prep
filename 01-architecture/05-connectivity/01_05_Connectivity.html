All Connectivity Facts:
  • ALL connections use HTTPS (port 443) - no other ports needed
  • ALL data in transit encrypted with TLS 1.2 minimum
  • NO direct connection to compute or storage - always through Cloud Services
  • Connection requires: Account identifier + Authentication credentials
  • Connection URL format: https://<account>.snowflakecomputing.com

-- View login attempts (useful for security auditing)
SELECT 
  event_timestamp,
  user_name,
  client_ip,
  reported_client_type,
  first_authentication_factor,
  second_authentication_factor,
  is_success,
  error_message
FROM SNOWFLAKE.ACCOUNT_USAGE.LOGIN_HISTORY
WHERE event_timestamp > DATEADD('day', -7, CURRENT_TIMESTAMP())
ORDER BY event_timestamp DESC
LIMIT 20;

Script 3: Session & Client Analysis

-- What clients are connecting to your account?
SELECT 
  reported_client_type,
  reported_client_version,
  COUNT(*) AS login_count,
  COUNT(DISTINCT user_name) AS unique_users
FROM SNOWFLAKE.ACCOUNT_USAGE.LOGIN_HISTORY
WHERE event_timestamp > DATEADD('day', -7, CURRENT_TIMESTAMP())
  AND is_success = 'YES'
GROUP BY reported_client_type, reported_client_version
ORDER BY login_count DESC;

8. Interview & Certification Q&A

Q1: What port does Snowflake use for connections?

A: Port 443 (HTTPS) exclusively. All communication is encrypted with TLS 1.2+. There's no need to open additional ports for Snowflake. This simplifies firewall configuration - you just need outbound HTTPS to *.snowflakecomputing.com.

Q2: What's the difference between SnowSQL and the Snowflake CLI (snow)?

A:

  • SnowSQL: Traditional SQL-focused CLI. Best for interactive SQL queries, scripting, PUT/GET file operations. Config in ~/.snowsql/config.
  • Snowflake CLI (snow): Modern DevOps-oriented CLI. Handles SQL execution PLUS Snowpark deployment, Streamlit apps, Native Apps, Git integration, object management. Config in ~/.snowflake/connections.toml.
The Snowflake CLI is the recommended tool going forward, but SnowSQL remains supported.

Q3: How does Snowflake connect to BI tools like Tableau and Power BI?

A:

  • Tableau: Uses a native Snowflake connector (JDBC-based internally). User provides account URL + credentials. Tableau pushes SQL to Snowflake for execution.
  • Power BI: Uses Snowflake ODBC driver. Supports both Import mode (data copied to Power BI) and DirectQuery mode (live queries to Snowflake).
In both cases, the BI tool sends SQL through the Snowflake driver and the virtual warehouse processes it. Result cache can serve repeated dashboard queries efficiently.

Q4: What is the connections.toml file?

A: ~/.snowflake/connections.toml is the modern connection configuration file for Snowflake. It stores connection profiles (account, user, password, warehouse, etc.) in TOML format. Benefits:

  • Shared across Snowflake CLI, Python connector, Snowpark, Cortex Code
  • Supports multiple named connections ([default], [dev], [prod])
  • Supports all auth methods (password, key-pair, SSO, OAuth)
  • Avoids hardcoding credentials in application code

Q5: What are the authentication methods supported by Snowflake connectors?

A:

  1. Username/Password: Basic auth (least secure, avoid in production)
  2. Key-Pair Authentication: RSA key pair (2048-bit min). Most secure for service accounts.
  3. External Browser (SSO): Opens browser for SAML/SSO login. Good for interactive use.
  4. OAuth: External OAuth or Snowflake OAuth. For applications and integrations.
  5. Programmatic Access Token (PAT): Token-based auth for automation (NEW)
  6. MFA (Multi-Factor): Duo push or TOTP as second factor

Q6: What is Snowpark and how does it differ from the Python Connector?

A:

Python ConnectorSnowpark
PurposeExecute SQL from PythonDataFrame API + deploy code TO Snowflake

Snowpark is preferred for data engineering and ML workloads because computation happens in Snowflake.

Q7: How does the Kafka connector work with Snowflake?

A: The Snowflake Kafka Connector runs as a Kafka Connect sink connector:

  • Reads messages from Kafka topics
  • Buffers records and writes them to a Snowflake internal stage as files
  • Uses Snowpipe to automatically load staged files into target tables
  • Each Kafka topic maps to a Snowflake table
  • Supports JSON and Avro formats
  • Near real-time loading (typically seconds of latency)

Q8: What is the Spark Connector used for?

A: The Snowflake Spark Connector allows bidirectional data transfer:

  • Read: Load Snowflake table data into Spark DataFrames (pushes filters to Snowflake)
  • Write: Write Spark DataFrames to Snowflake tables (bulk load via internal stage)
  • Query Pushdown: Can push entire Spark operations to Snowflake for execution
Common in environments transitioning from Spark/Databricks to Snowflake, or using Spark for ML with Snowflake as storage. Note: Snowpark Connect now offers a simpler alternative for PySpark code.

Q9: Can Snowflake integrate with Git repositories?

A: Yes, multiple ways:

  • Git Integration (native): CREATE GIT REPOSITORY - clone a repo as a Snowflake stage. Access files directly from SQL.
  • Snowflake CLI: snow git commands for repository management
  • CI/CD: Use SnowSQL or Snowflake CLI in GitHub Actions/Jenkins/GitLab CI pipelines to deploy changes
  • SchemaChange/Flyway: Database migration tools with Snowflake support

Q10: What networking considerations are important for Snowflake connectivity?

A:

  • Port 443 only: All traffic over HTTPS
  • Network Policies: IP allow/block lists (can be applied per account or per user)
  • Private Connectivity: AWS PrivateLink, Azure Private Link, GCP Private Service Connect (Business Critical+)
  • Proxy Support: Most drivers support HTTP proxy configuration
  • DNS: Must resolve *.snowflakecomputing.com (or private endpoints)
  • Firewall: Outbound HTTPS to Snowflake endpoints + cloud storage (S3/Blob/GCS for data transfer)
