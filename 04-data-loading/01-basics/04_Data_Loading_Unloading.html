1. Stages

What Are Stages?

Stages are locations where data files are stored before being loaded into Snowflake tables (or after being unloaded). Think of them as "landing zones."

Stage Types

User StageSnowflake internal (per user)Auto-created per user@~
Table StageSnowflake internal (per table)Auto-created per table@%table_name
Named Internal StageSnowflake internal (explicit)CREATE STAGE@stage_name
External StageS3 / Azure Blob / GCSCREATE STAGE + credentials@ext_stage_name

Creating Stages

-- Named Internal Stage
CREATE STAGE my_internal_stage
  FILE_FORMAT = (TYPE = CSV FIELD_DELIMITER = ',' SKIP_HEADER = 1)
  COMMENT = 'Internal stage for CSV loads';

-- External Stage (AWS S3)
CREATE STAGE my_s3_stage
  URL = 's3://my-bucket/path/'
  STORAGE_INTEGRATION = my_s3_integration  -- or CREDENTIALS
  FILE_FORMAT = (TYPE = PARQUET);

-- External Stage (Azure Blob)
CREATE STAGE my_azure_stage
  URL = 'azure://myaccount.blob.core.windows.net/container/path/'
  STORAGE_INTEGRATION = my_azure_integration;

-- External Stage (GCS)
CREATE STAGE my_gcs_stage
  URL = 'gcs://my-bucket/path/'
  STORAGE_INTEGRATION = my_gcs_integration;

-- List files in a stage
LIST @my_internal_stage;
LIST @~;  -- user stage
LIST @%my_table;  -- table stage
Exam Tip - Stage Symbols:
  • @~ = User stage (tilde = personal)
  • @%table_name = Table stage (percent = per-table)
  • @stage_name = Named stage (at + name)
  • PUT command: Only works with internal stages (not external)
  • External stages: Files uploaded directly to cloud storage (not via PUT)

Storage Integration (for External Stages)

-- Storage Integration eliminates embedded credentials
CREATE STORAGE INTEGRATION my_s3_integration
  TYPE = EXTERNAL_STAGE
  STORAGE_PROVIDER = 'S3'
  STORAGE_AWS_ROLE_ARN = 'arn:aws:iam::123456789:role/snowflake-role'
  ENABLED = TRUE
  STORAGE_ALLOWED_LOCATIONS = ('s3://my-bucket/allowed-path/');

-- Benefits over inline credentials:
-- 1. Centralized credential management
-- 2. Can restrict to specific paths (STORAGE_ALLOWED_LOCATIONS)
-- 3. Uses IAM role assumption (no access keys in SQL)
-- 4. ACCOUNTADMIN creates once, grants USAGE to other roles

-- Create named file format (reusable)
CREATE FILE FORMAT my_csv_format
  TYPE = CSV
  FIELD_DELIMITER = ','
  RECORD_DELIMITER = '\n'
  SKIP_HEADER = 1
  NULL_IF = ('NULL', 'null', '')
  EMPTY_FIELD_AS_NULL = TRUE
  FIELD_OPTIONALLY_ENCLOSED_BY = '"'
  COMPRESSION = AUTO;

CREATE FILE FORMAT my_json_format
  TYPE = JSON
  STRIP_OUTER_ARRAY = TRUE
  STRIP_NULL_VALUES = FALSE;

CREATE FILE FORMAT my_parquet_format
  TYPE = PARQUET
  SNAPPY_COMPRESSION = TRUE;

-- Use inline (without named format)
COPY INTO my_table FROM @my_stage
  FILE_FORMAT = (TYPE = CSV SKIP_HEADER = 1 FIELD_DELIMITER = '|');
File Format Key Facts:
  • Can be defined: inline in COPY, in stage definition, or as named object
  • Priority: COPY statement > Stage definition > Named format
  • Parquet/Avro/ORC: Schema embedded in file (auto-detected)
  • CSV: Schema must match target table column order
  • COMPRESSION = AUTO: Snowflake auto-detects gzip, bzip2, deflate, etc.

3. COPY INTO (Data Loading)

Basic COPY INTO Syntax

-- Basic load from stage
COPY INTO my_table
  FROM @my_stage/path/
  FILE_FORMAT = (FORMAT_NAME = my_csv_format)
  PATTERN = '.*\.csv'          -- regex for file selection
  ON_ERROR = 'CONTINUE'        -- error handling
  PURGE = TRUE;                -- delete files after load

-- Load with transformations (column reordering, casting)
COPY INTO my_table (col1, col3, col2)
  FROM (
    SELECT $1, $3::DATE, $2::NUMBER
    FROM @my_stage/data.csv
  )
  FILE_FORMAT = (TYPE = CSV SKIP_HEADER = 1);

-- Load JSON into VARIANT column
COPY INTO json_table (raw_data)
  FROM @my_stage/data.json
  FILE_FORMAT = (TYPE = JSON);

-- Load Parquet with column matching
COPY INTO my_table
  FROM @my_stage/
  FILE_FORMAT = (TYPE = PARQUET)
  MATCH_BY_COLUMN_NAME = CASE_INSENSITIVE;

COPY INTO Options

OptionValuesPurpose
ON_ERRORABORT_STATEMENT, CONTINUE, SKIP_FILE, SKIP_FILE_n%What to do when errors occur
PURGETRUE/FALSEDelete staged files after successful load
FORCETRUE/FALSEReload files even if already loaded (bypasses dedup)
PATTERNRegex stringFilter which files to load
FILESList of filenamesLoad specific files only
VALIDATION_MODERETURN_ERRORS, RETURN_n_ROWSDry run - validate without loading
SIZE_LIMITBytesMax data size to load per statement
MATCH_BY_COLUMN_NAMECASE_SENSITIVE, CASE_INSENSITIVE, NONEMatch Parquet/Avro columns by name
COPY Deduplication: Snowflake tracks which files have been loaded (64-day metadata). Re-running COPY on the same file does NOTHING (silently skips). Use FORCE = TRUE to reload, or PURGE = TRUE to remove after load.

Snowpipe (Continuous Loading)

-- Create a Snowpipe
CREATE PIPE my_pipe
  AUTO_INGEST = TRUE      -- Trigger on S3 event notification
  AS
  COPY INTO my_table
  FROM @my_external_stage
  FILE_FORMAT = (TYPE = JSON);

-- Check pipe status
SELECT SYSTEM$PIPE_STATUS('my_pipe');

WHERE pipe_name = 'MY_PIPE'
ORDER BY start_time DESC;

ALTER PIPE my_pipe REFRESH;

5. Data Unloading

-- Unload to internal stage
COPY INTO @my_stage/output/
  FROM my_table
  FILE_FORMAT = (TYPE = CSV HEADER = TRUE)
  OVERWRITE = TRUE
  MAX_FILE_SIZE = 67108864;  -- 64 MB per file

-- Unload with query transformation
COPY INTO @my_stage/report/
  FROM (
    SELECT category, SUM(amount) AS total
    FROM my_table
    GROUP BY category
  )
  FILE_FORMAT = (TYPE = PARQUET)
  HEADER = TRUE;

-- Unload to external stage (S3)
COPY INTO 's3://my-bucket/exports/'
  FROM my_table
  STORAGE_INTEGRATION = my_s3_integration
  FILE_FORMAT = (TYPE = CSV)
  PARTITION BY ('date_col')  -- creates subdirectories by date
  MAX_FILE_SIZE = 104857600;  -- 100 MB

-- Single file output (use SINGLE = TRUE)
COPY INTO @my_stage/single_file
  FROM my_table
  FILE_FORMAT = (TYPE = CSV)
  SINGLE = TRUE
  MAX_FILE_SIZE = 5368709120;  -- 5 GB max for single

6. Loading Best Practices

Optimal File Sizing:
  • Target: 100-250 MB compressed per file
  • Too small (< 10 MB): Overhead per file, slow loading
  • Too large (> 5 GB): Can't parallelize within one file
  • Snowflake loads files in PARALLEL across warehouse nodes
  • Number of files >= number of warehouse nodes for max parallelism
PracticeWhy
Split large files into 100-250 MB chunksEnables parallel loading across nodes
Use compressed files (gzip, snappy)Faster transfer, auto-decompressed
Use Parquet/Avro over CSV for analyticsBetter compression, schema enforcement, faster
Use COPY with VALIDATION_MODE firstCatch errors before loading production
Use PURGE = TRUE in productionClean up after successful load
Match warehouse size to load volumeMore nodes = more parallel file loading
Use Snowpipe for continuous loadsAutomatic, serverless, no scheduling needed
Use Storage Integration over credentialsMore secure, centralized, auditable

8. Interview & Certification Q&A

Q1: What are the different types of stages and when to use each?

A:

  • User Stage (@~): Personal staging area. Quick ad-hoc uploads. Can't be shared or granted to others. Good for individual analyst file uploads.
  • Table Stage (@%table): Auto-created per table. Files loaded ONLY to that table. Can't be shared. Good for table-specific loads.
  • Named Internal Stage (@name): Most flexible. Can define file format, can GRANT access to roles. Good for shared team loading, organized data pipelines.
  • External Stage: Points to S3/Azure/GCS. Data stays in cloud storage. Good for data lakes, cross-system access, large-scale loads.

Q2: What's the difference between Snowpipe and COPY INTO?

A:

COPY INTOSnowpipe
TriggerManual (user runs SQL)Automatic (file arrival event)
ComputeYour warehouse (credits)Serverless (separate billing)
SchedulingCron/Tasks or manualEvent-driven (real-time)
Best forLarge scheduled batchesContinuous small file streams
File tracking64-day dedup window14-day dedup window

Q3: What happens if you run COPY INTO on a file that was already loaded?

A: Snowflake maintains a 64-day load metadata history. If the same file (by name + checksum) was already loaded:

  • Default behavior: Silently skipped (no error, no duplicate rows)
  • With FORCE = TRUE: Loads again (creates duplicates!)
  • This dedup prevents accidental re-loads
  • After 64 days: metadata expires, file CAN be re-loaded accidentally

Q4: What's the optimal file size for loading data?

A: 100-250 MB compressed per file is optimal:

  • Each file is loaded by one thread on one warehouse node
  • Multiple files = parallel loading across all nodes
  • Ideal: number of files >= number of nodes (e.g., Medium WH has 4 nodes, use 4+ files)
  • Too small (<10 MB): per-file overhead dominates
  • Too large (>5 GB): single node bottleneck, no parallelism within file

Q5: How do you load semi-structured data (JSON/Parquet) into Snowflake?

A: Two approaches:

  1. Load into VARIANT column: Preserves raw structure 
    COPY INTO json_table (raw_json) FROM @stage FILE_FORMAT = (TYPE=JSON);
    Then query with dot notation: raw_json:name::STRING
  2. Load with column matching (Parquet/Avro): Auto-maps to typed columns 
    COPY INTO typed_table FROM @stage FILE_FORMAT = (TYPE=PARQUET) MATCH_BY_COLUMN_NAME = CASE_INSENSITIVE;
Parquet is preferred for analytics (columnar, compressed, typed). JSON into VARIANT for flexibility.

Q6: What is a Storage Integration and why use it over credentials?

A: A Storage Integration is a Snowflake object that securely connects to external cloud storage:

  • Security: Uses IAM role assumption (not access keys in SQL)
  • Centralization: One integration, many stages
  • Restriction: STORAGE_ALLOWED_LOCATIONS limits which paths can be accessed
  • Audit: Integration usage tracked in access logs
  • Separation of duties: ACCOUNTADMIN creates integration, other roles use it
Always prefer Storage Integration over inline CREDENTIALS in production.

Q7: What is Snowpipe Streaming and how is it different from regular Snowpipe?

A:

  • Regular Snowpipe: File-based. Files land in stage --> event triggers --> Snowpipe loads file. ~1 minute latency.
  • Snowpipe Streaming: Row-based. Application sends rows directly via SDK (Java/Python). No file staging needed. Sub-second latency.
Streaming is used by the Snowflake Kafka Connector v2+ and is ideal for IoT, clickstream, CDC where sub-second ingestion matters. Both use serverless compute.

Q8: How do you troubleshoot a failed COPY INTO?

A:

  1. VALIDATE function: SELECT * FROM TABLE(VALIDATE(table, JOB_ID=>'_last')) - shows errors from last load
  2. COPY_HISTORY: Check INFORMATION_SCHEMA.COPY_HISTORY for status and error messages
  3. VALIDATION_MODE: Re-run with VALIDATION_MODE='RETURN_ERRORS' to see what would fail
  4. Common issues: Data type mismatch, extra columns, null in NOT NULL column, date format wrong, encoding issues
  5. ON_ERROR options: CONTINUE (skip bad rows), SKIP_FILE (skip entire file), ABORT_STATEMENT (fail all)
