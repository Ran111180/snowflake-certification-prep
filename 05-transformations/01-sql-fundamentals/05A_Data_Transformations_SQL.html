1. SQL Fundamentals (DDL/DML)

DDL Unique to Snowflake

-- CREATE OR REPLACE (atomic swap - no downtime)
CREATE OR REPLACE TABLE my_table (id INT, name VARCHAR);
-- Drops old table + creates new in one atomic operation
-- Old table goes to Time Travel (can UNDROP)

-- CREATE TABLE ... AS SELECT (CTAS)
CREATE TABLE summary AS SELECT category, SUM(amount) AS total FROM orders GROUP BY category;

-- CREATE TABLE ... LIKE (structure only, no data)
CREATE TABLE orders_backup LIKE orders;

-- CREATE TABLE ... CLONE (zero-copy with data)
CREATE TABLE orders_dev CLONE orders;

-- UNDROP (recover from accidental drops)
DROP TABLE my_table;
UNDROP TABLE my_table;  -- Recovered from Time Travel!

-- SWAP (atomic table swap)
ALTER TABLE staging_orders SWAP WITH production_orders;
-- Both tables exchanged instantly - great for blue/green deployments

DML Essentials

-- MERGE (upsert - most important DML for pipelines)
MERGE INTO target USING source ON target.id = source.id
WHEN MATCHED THEN UPDATE SET target.amount = source.amount
WHEN NOT MATCHED THEN INSERT (id, amount) VALUES (source.id, source.amount);

-- INSERT OVERWRITE (replace partition-like behavior)
INSERT OVERWRITE INTO daily_summary
SELECT order_date, SUM(amount) FROM orders 
WHERE order_date = CURRENT_DATE() GROUP BY order_date;

-- Multi-table INSERT (one scan, multiple targets)
INSERT ALL
  WHEN amount > 1000 THEN INTO high_value_orders
  WHEN amount <= 1000 THEN INTO standard_orders
SELECT * FROM new_orders;

-- TRUNCATE vs DELETE
TRUNCATE TABLE my_table;  -- Instant, no Time Travel (immediately purges)
DELETE FROM my_table;      -- Row by row, creates Time Travel versions
Exam Gotcha - TRUNCATE vs DELETE:
  • TRUNCATE: Instant, removes ALL data, minimal Time Travel (metadata only), cannot filter rows
  • DELETE: Can use WHERE clause, creates Time Travel copies of removed partitions, slower on large tables
  • Both are DML. TRUNCATE is NOT DDL in Snowflake (unlike some databases).

2. Snowflake-Specific SQL Features

QUALIFY Clause (Snowflake Extension)

-- QUALIFY: Filter on window function results (like HAVING for aggregates)
-- Instead of wrapping in subquery:

-- Traditional (verbose):
SELECT * FROM (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC) AS rn
  FROM employees
) WHERE rn = 1;

-- Snowflake QUALIFY (elegant):
SELECT * FROM employees
QUALIFY ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC) = 1;

-- Get top 3 per category
SELECT * FROM products
QUALIFY RANK() OVER (PARTITION BY category ORDER BY revenue DESC) <= 3;

-- Deduplicate (keep latest per key)
SELECT * FROM raw_events
QUALIFY ROW_NUMBER() OVER (PARTITION BY event_id ORDER BY event_ts DESC) = 1;
Exam Tip: QUALIFY is Snowflake-specific (not standard SQL). It executes AFTER window functions are computed. Execution order: FROM > WHERE > GROUP BY > HAVING > Window Functions > QUALIFY > ORDER BY > LIMIT.

GENERATOR & Sequences

-- Generate rows (synthetic data, date spines)
SELECT SEQ4() AS row_num, 
       DATEADD(day, SEQ4(), '2024-01-01')::DATE AS date_val
FROM TABLE(GENERATOR(ROWCOUNT => 365));

-- Date spine (all dates in a range)
SELECT DATEADD(day, ROW_NUMBER() OVER (ORDER BY 1) - 1, '2024-01-01')::DATE AS dt
FROM TABLE(GENERATOR(ROWCOUNT => 365));

-- Sequences
CREATE SEQUENCE order_seq START = 1000 INCREMENT = 1;
SELECT order_seq.NEXTVAL;  -- 1000, 1001, 1002...

SAMPLE / TABLESAMPLE

-- Random sample (different methods)
SELECT * FROM large_table SAMPLE (10);           -- 10% of rows (approximate)
SELECT * FROM large_table SAMPLE (100 ROWS);     -- Exactly 100 rows
SELECT * FROM large_table TABLESAMPLE BERNOULLI (1);  -- 1% Bernoulli sampling
SELECT * FROM large_table TABLESAMPLE SYSTEM (10);    -- 10% block-level (faster)

FLATTEN (Semi-structured - also used in general)

-- LATERAL FLATTEN: Explode arrays/objects into rows
SELECT 
  order_id,
  f.value:product_id::INT AS product_id,
  f.value:quantity::INT AS quantity
FROM orders,
LATERAL FLATTEN(input => order_items) f;

PIVOT and UNPIVOT

-- PIVOT: Rows to columns
SELECT * FROM monthly_sales
PIVOT (SUM(revenue) FOR month IN ('JAN', 'FEB', 'MAR', 'APR'))
AS p;

-- UNPIVOT: Columns to rows
SELECT * FROM quarterly_report
UNPIVOT (revenue FOR quarter IN (Q1, Q2, Q3, Q4));

Window Function Categories

Ranking Functions Compared

  DATA: Scores = [100, 90, 90, 80, 70]

  ROW_NUMBER: 1, 2, 3, 4, 5  (always unique, arbitrary for ties)
  RANK:       1, 2, 2, 4, 5  (same rank for ties, gaps after)
  DENSE_RANK: 1, 2, 2, 3, 4  (same rank for ties, NO gaps)
  NTILE(2):   1, 1, 1, 2, 2  (divide into N equal groups)
  
-- Running total
SELECT order_date, amount,
  SUM(amount) OVER (ORDER BY order_date) AS running_total
FROM orders;

-- Moving average (last 7 days)
SELECT order_date, amount,
  AVG(amount) OVER (ORDER BY order_date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS ma_7day
FROM daily_sales;

-- Year-over-year comparison with LAG
SELECT month, revenue,
  LAG(revenue, 12) OVER (ORDER BY month) AS revenue_last_year,
  revenue - LAG(revenue, 12) OVER (ORDER BY month) AS yoy_change
FROM monthly_revenue;

-- Percent of total per group
SELECT dept, employee, salary,
  ROUND(salary / SUM(salary) OVER (PARTITION BY dept) * 100, 1) AS pct_of_dept
FROM employees;

4. Semi-Structured Data

VARIANT, OBJECT, ARRAY Data Types

TypeStoresExample
VARIANTAny JSON value (object, array, scalar){"name":"Alice","age":30}
OBJECTJSON object (key-value pairs){"key1":"val1","key2":"val2"}
ARRAYJSON array (ordered list)[1, 2, 3, "four"]

Accessing Semi-Structured Data

-- Given: column "data" contains {"customer":{"name":"Alice","addresses":[{"city":"NYC"},{"city":"LA"}]}}

-- Dot notation (case-insensitive by default for VARIANT)
SELECT data:customer:name::VARCHAR AS customer_name FROM my_table;

-- Bracket notation (case-sensitive)
SELECT data['customer']['name']::VARCHAR AS customer_name FROM my_table;

-- Array access (0-based index)
SELECT data:customer:addresses[0]:city::VARCHAR AS first_city FROM my_table;

-- IMPORTANT: Always CAST (::) when extracting from VARIANT!
-- Without cast: returns VARIANT type (won't work in WHERE efficiently)
-- With cast (::VARCHAR, ::INT, ::DATE): proper type, enables pruning

FLATTEN - The Key Function

-- Example JSON: {"order_id":1,"items":[{"sku":"A1","qty":2},{"sku":"B2","qty":1}]}

-- FLATTEN explodes array into rows
SELECT 
  raw:order_id::INT AS order_id,
  f.index AS item_index,
  f.value:sku::VARCHAR AS sku,
  f.value:qty::INT AS qty
FROM orders_json,
LATERAL FLATTEN(input => raw:items) f;

-- Result:
-- order_id | item_index | sku | qty
-- 1        | 0          | A1  | 2
-- 1        | 1          | B2  | 1

-- FLATTEN with OUTER (keep rows even if array is NULL/empty)
SELECT o.id, f.value::VARCHAR AS tag
FROM orders o,
LATERAL FLATTEN(input => o.tags, OUTER => TRUE) f;

-- Recursive FLATTEN (nested objects)
SELECT 
  f.key AS field_name,
  f.value::VARCHAR AS field_value,
  f.path AS json_path
FROM my_table,
LATERAL FLATTEN(input => raw_json, RECURSIVE => TRUE) f
WHERE f.value IS NOT NULL;

Construction Functions

-- Build JSON objects
SELECT OBJECT_CONSTRUCT('name', name, 'email', email, 'active', TRUE) AS json_obj
FROM customers;

-- Build arrays
SELECT ARRAY_CONSTRUCT(1, 2, 3, 4, 5) AS my_array;
SELECT ARRAY_AGG(product_name) AS all_products FROM orders GROUP BY order_id;

-- Parse/convert
SELECT PARSE_JSON('{"key": "value"}') AS parsed;
SELECT TO_JSON(OBJECT_CONSTRUCT('a', 1, 'b', 2)) AS json_string;
SELECT TRY_PARSE_JSON(maybe_json_column) AS safe_parsed;  -- Returns NULL if invalid
Semi-Structured Key Facts for Exam:
  • VARIANT can store up to 16 MB per value
  • Snowflake auto-optimizes VARIANT (detects repeated keys, stores columnar internally)
  • Always CAST when extracting (::VARCHAR, ::INT) for performance and type safety
  • FLATTEN = most important function for semi-structured processing
  • LATERAL keyword required before FLATTEN in FROM clause
  • OUTER => TRUE in FLATTEN = preserve parent rows if array is null/empty
  • Can query VARIANT with standard WHERE/GROUP BY after casting

5. Advanced SQL Patterns

CTEs and Recursive CTEs

-- Standard CTE (WITH clause)
WITH monthly_totals AS (
  SELECT DATE_TRUNC('month', order_date) AS month, SUM(amount) AS total
  FROM orders GROUP BY 1
),
running AS (
  SELECT month, total, SUM(total) OVER (ORDER BY month) AS cumulative
  FROM monthly_totals
)
SELECT * FROM running;

-- Recursive CTE (tree/hierarchy traversal)
WITH RECURSIVE org_chart AS (
  -- Anchor: top-level managers (no manager)
  SELECT employee_id, name, manager_id, 1 AS level
  FROM employees WHERE manager_id IS NULL
  
  UNION ALL
  
  -- Recursive: join to find direct reports
  SELECT e.employee_id, e.name, e.manager_id, oc.level + 1
  FROM employees e
  JOIN org_chart oc ON e.manager_id = oc.employee_id
)
SELECT * FROM org_chart ORDER BY level, name;

GROUP BY Extensions

-- GROUPING SETS (multiple groupings in one query)
SELECT region, category, SUM(sales)
FROM sales_data
GROUP BY GROUPING SETS ((region, category), (region), (category), ())
ORDER BY region, category;
-- Returns: per region+category, per region, per category, and grand total

-- ROLLUP (hierarchical subtotals)
SELECT region, category, SUM(sales)
FROM sales_data
GROUP BY ROLLUP (region, category);
-- Returns: per region+category, subtotal per region, grand total

-- CUBE (all possible combinations)
SELECT region, category, SUM(sales)
FROM sales_data
GROUP BY CUBE (region, category);

MATCH_RECOGNIZE (Pattern Matching)

-- Find sequences in ordered data (e.g., stock price patterns)
SELECT * FROM stock_prices
MATCH_RECOGNIZE (
  PARTITION BY symbol
  ORDER BY trading_date
  MEASURES
    FIRST(DOWN.trading_date) AS start_date,
    LAST(UP.trading_date) AS end_date,
    COUNT(*) AS pattern_length
  ONE ROW PER MATCH
  PATTERN (DOWN+ UP+)  -- One or more downs followed by one or more ups
  DEFINE
    DOWN AS price < LAG(price),
    UP AS price > LAG(price)
);

7. Interview & Certification Q&A

Q1: What is the QUALIFY clause and when do you use it?

A: QUALIFY filters results of window functions (like HAVING filters aggregates). It's Snowflake-specific:

  • Executes AFTER window functions are computed
  • Replaces the need for subquery wrappers
  • Most common use: TOP-N per group, deduplication
  • Example: SELECT * FROM t QUALIFY ROW_NUMBER() OVER (PARTITION BY key ORDER BY ts DESC) = 1
Execution order: FROM > WHERE > GROUP BY > HAVING > Window Functions > QUALIFY > ORDER BY > LIMIT

Q2: How do you handle JSON data in Snowflake?

A:

  1. Storage: Use VARIANT column type (stores any JSON, up to 16 MB per value)
  2. Loading: COPY INTO with TYPE=JSON, or PARSE_JSON() for inline
  3. Querying: Dot notation (col:key::TYPE) or bracket (col['key'])
  4. Flattening: LATERAL FLATTEN to explode arrays into rows
  5. Performance: Snowflake auto-detects repeated JSON keys and optimizes storage (columnar-like)
  6. Always cast: Use ::VARCHAR, ::INT etc. for proper typing and pruning

Q3: Explain the difference between ROW_NUMBER, RANK, and DENSE_RANK.

A: For values [100, 90, 90, 80]:

  • ROW_NUMBER: 1, 2, 3, 4 - Always unique. Ties broken arbitrarily. Use for dedup.
  • RANK: 1, 2, 2, 4 - Same rank for ties, then SKIP (gap). Use for competition ranking.
  • DENSE_RANK: 1, 2, 2, 3 - Same rank for ties, NO gap. Use when you need consecutive ranks.

Q4: What is LATERAL FLATTEN and when do you use OUTER => TRUE?

A:

  • LATERAL FLATTEN: Explodes a VARIANT array/object into multiple rows (one per element). LATERAL means it references the outer table's columns.
  • OUTER => TRUE: Preserves the parent row even if the array is NULL or empty (like LEFT JOIN behavior). Without it, rows with NULL/empty arrays are dropped.
  • Example: Order has no items array → with OUTER=TRUE: order row kept with NULL item values. Without: order row disappears.

Q5: What's the difference between CREATE OR REPLACE and DROP + CREATE?

A:

  • CREATE OR REPLACE: Atomic operation. Old table drops and new one creates in one transaction. Old table is in Time Travel. Any grants on the old table are LOST.
  • DROP + CREATE: Two separate operations. Brief moment where table doesn't exist. Same end result but not atomic.
  • Key gotcha: CREATE OR REPLACE removes all existing GRANTs! If roles had SELECT on the old table, they lose it. Use ALTER TABLE if you need to keep grants.

Q6: How do you do a running total and moving average in Snowflake?

A: 

-- Running total (cumulative sum)
SUM(amount) OVER (ORDER BY date_col ROWS UNBOUNDED PRECEDING)

-- Moving average (last 7 rows)
AVG(amount) OVER (ORDER BY date_col ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)

-- Moving average (last 7 days - time-based)
AVG(amount) OVER (ORDER BY date_col RANGE BETWEEN INTERVAL '6 days' PRECEDING AND CURRENT ROW)
Key difference: ROWS = physical row count, RANGE = logical value range.

Q7: How does INSERT OVERWRITE differ from DELETE + INSERT?

A:

  • INSERT OVERWRITE: Atomically replaces ALL data in the table with the new query results. One transaction. Used for full-refresh patterns.
  • DELETE + INSERT: Two operations. Data temporarily gone between them (if not in a transaction). More Time Travel storage (delete creates versions).
  • INSERT OVERWRITE advantages: Atomic, less Time Travel storage, simpler logic for full-refresh tables.
