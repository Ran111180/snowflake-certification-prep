3. Cortex Search

What Is Cortex Search?

A fully managed hybrid search service (keyword + semantic/vector) over your text data.

  USER QUERY: "How do I reset my password?"
       |
       v
  +----------------------------+
  | CORTEX SEARCH SERVICE      |
  |                            |
  | 1. Keyword search (BM25)   |  -- Finds exact matches
  | 2. Vector search (ANN)     |  -- Finds semantic matches
  | 3. Hybrid ranking          |  -- Combines both signals
  | 4. Return top-K results    |
  +----------------------------+
       |
       v
  RESULTS: Relevant documents ranked by combined score
  
-- Create a Cortex Search Service
CREATE CORTEX SEARCH SERVICE support_search
  ON text_column
  ATTRIBUTES category, priority    -- Filterable metadata
  WAREHOUSE = COMPUTE_WH
  TARGET_LAG = '1 hour'            -- How fresh the index should be
  AS (
    SELECT doc_id, text_column, category, priority
    FROM knowledge_base
  );

-- Query the search service (via SQL or REST API)
SELECT * FROM TABLE(
  CORTEX_SEARCH('support_search', 
    'how to reset password',         -- Query
    TOP_K => 5,                      -- Return top 5
    FILTER => {'category': 'auth'}   -- Optional filter
  )
);
Cortex Search Use Cases:
  • Enterprise search over internal docs/knowledge bases
  • RAG (Retrieval Augmented Generation) - retrieve context before LLM call
  • Customer support: Find relevant articles for tickets
  • Auto-refreshes as source data changes (TARGET_LAG)
  • Combines keyword accuracy + semantic understanding

Semantic Model/View

-- Semantic View: Defines business meaning of your data
CREATE SEMANTIC VIEW revenue_model AS
  -- Tables
  TABLES (
    sales_fact REFERENCES DB.SCHEMA.SALES,
    dim_region REFERENCES DB.SCHEMA.REGIONS
  )
  -- Relationships
  RELATIONSHIPS (
    sales_fact.region_id = dim_region.region_id
  )
  -- Metrics (business calculations)
  METRICS (
    total_revenue AS SUM(sales_fact.amount),
    order_count AS COUNT(DISTINCT sales_fact.order_id),
    avg_order_value AS total_revenue / order_count
  )
  -- Dimensions (groupable attributes)
  DIMENSIONS (
    region AS dim_region.region_name,
    quarter AS DATE_TRUNC('quarter', sales_fact.order_date)
  )
  -- Verified queries (known-good examples for accuracy)
  VERIFIED_QUERIES (
    'total revenue last quarter' => 'SELECT SUM(amount) FROM sales WHERE ...'
  );

9. Interview & Certification Q&A

Q1: What is Snowflake Cortex and how does it differ from using external ML platforms?

A:

  • Cortex: AI/ML runs inside Snowflake, on your data, with full governance. No data extraction needed.
  • External (SageMaker, Vertex AI): Must extract data, manage infra, handle security separately.
  • Key advantages: Data doesn't leave Snowflake, RBAC/masking applies to AI outputs, SQL-callable (no Python needed for basic use), serverless compute, pay-per-use.

Q2: What's the difference between AI_COMPLETE and the built-in ML functions (FORECAST, etc.)?

A:

  • AI_COMPLETE: General-purpose LLM. Takes a prompt, returns text. For generation, summarization, reasoning, classification, extraction. Uses pre-trained models (Arctic, Llama, Mistral).
  • ML Functions (FORECAST, ANOMALY, CLASSIFY): Specialized models TRAINED ON YOUR DATA. You provide training data, Snowflake trains a custom model, then you predict. Specific to time-series or classification tasks.
AI_COMPLETE = pre-trained, general. ML Functions = custom-trained on your data.

Q3: How does Cortex Search work and what is RAG?

A:

  • Cortex Search: Managed hybrid search service combining keyword (BM25) + vector/semantic search. You define a search service on a text column, Snowflake builds and maintains the index.
  • RAG (Retrieval Augmented Generation): Pattern where you FIRST search for relevant documents, THEN pass them as context to an LLM. Reduces hallucination because the LLM answers based on your actual data.
  • Flow: User question → Cortex Search (find relevant docs) → AI_COMPLETE (answer using those docs as context)

Q4: What is a Semantic View and why does Cortex Analyst need it?

A: A Semantic View provides business context that LLMs need to generate accurate SQL:

  • Table relationships: Which tables join on which keys
  • Metric definitions: "Revenue" = SUM(amount), "Active users" = COUNT(DISTINCT user WHERE last_login > 30d ago)
  • Dimensions: How data can be grouped/filtered (by region, quarter, category)
  • Verified queries: Known-good SQL for common questions (ground truth for accuracy)
Without a semantic model, the LLM would guess table/column names and metrics - leading to incorrect SQL.

Q5: What are Cortex Agents and how are they different from just calling AI_COMPLETE?

A:

  • AI_COMPLETE: Single LLM call. Input → output. No reasoning, no tool use, no multi-step.
  • Cortex Agents: Multi-step AI workflows. The agent can:
    1. Understand the request and plan steps
    2. Call TOOLS: SQL queries (via Analyst), search (via Cortex Search), generate (via Complete)
    3. Iterate: Look at results, decide next action
    4. Combine results into final answer
  • Think of it as: AI_COMPLETE = calculator, Agent = analyst who uses multiple tools to solve a problem.

Q6: How do you build a forecasting model in Snowflake?

A: Using the built-in ML.FORECAST function (no Python needed): 

-- 1. Prepare time-series data (date + metric columns)
-- 2. Create model (trains automatically)
CREATE SNOWFLAKE.ML.FORECAST my_forecast(
  INPUT_DATA => TABLE(SELECT date_col, value_col FROM history),
  TIMESTAMP_COLNAME => 'date_col',
  TARGET_COLNAME => 'value_col'
);
-- 3. Generate predictions
CALL my_forecast!FORECAST(FORECASTING_PERIODS => 30);
It handles seasonality, trends, and confidence intervals automatically. For more control, use Snowpark ML with scikit-learn/XGBoost.

Q7: How would you implement a customer support chatbot using Snowflake Cortex?

A: Architecture:

  1. Knowledge base: Load support articles/FAQs into a Snowflake table
  2. Cortex Search Service: Create search service on the knowledge base text
  3. RAG pipeline: When user asks question → Search for top-5 relevant articles → Pass articles + question to AI_COMPLETE as context
  4. Or use Cortex Agent: Define agent with search_tool + complete_tool, give it instructions about tone and scope
  5. Frontend: Streamlit in Snowflake app with chat interface
All within Snowflake - no external vector DB, no API gateway, no separate ML infra needed.

Q8: What LLM models are available in Snowflake Cortex?

A: Multiple model families:

  • Snowflake Arctic: Snowflake's own model family (optimized for enterprise SQL/data tasks)
  • Meta Llama: Llama 3.1, 3.2, 3.3 (various sizes: 8B, 70B, 405B)
  • Mistral: Mistral Large, Mixtral
  • Others: Reka, DeepSeek models available depending on region
  • Embedding models: snowflake-arctic-embed-m (for vector search)
You choose the model per call: AI_COMPLETE('llama3.1-70b', prompt). Larger models = better quality but slower/costlier.
