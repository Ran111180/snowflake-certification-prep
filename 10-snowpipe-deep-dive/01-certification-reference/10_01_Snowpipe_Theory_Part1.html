1. What is Snowpipe?

Definition

Snowpipe is Snowflake's continuous, serverless data ingestion service that loads data from files in stages into tables within minutes of the file's arrival.

AspectDetail
ComputeSnowflake-managed (serverless) - does NOT use your warehouse
Latency~1 minute from notification to data available
BillingPer-file basis (~0.06 credits per 1000 files queued)
Trigger Methods1) Cloud event notifications (auto-ingest) 2) REST API calls
File SourcesInternal stages, External stages (S3, Azure Blob, GCS)
Load UnitMicro-batches (individual files or small groups)
Deduplication14-day load metadata prevents re-loading same file

Snowpipe vs Bulk COPY INTO

FeatureSnowpipeBulk COPY INTO
ComputeSnowflake-managed (serverless)Your virtual warehouse
TriggerEvent notification / REST APIManual / scheduled via Task
Latency~1 minuteDepends on schedule
Cost ModelPer-file (credits for compute time)Warehouse credits (time-based)

File Size Sweet Spot100-250 MB compressedAny size (larger = more efficient)
Load History Retention14 days64 days (LOAD_HISTORY in Account Usage)
TransformationsLimited (column reorder, CAST, omit)Full SELECT with expressions
PATTERN BehaviorStage URL trimmed BEFORE regex appliedRegex applied to FULL path
TransactionEach file = separate transactionAll files = single transaction

2. Architecture & How It Works

Auto-Ingest Flow (External Stage):

[Cloud Storage] --new file--> [Event Notification] --message--> [Snowflake SQS/Queue]
|
v
[Snowpipe Service] --reads file--> [Stage] --COPY INTO--> [Target Table]
|
v
[Load Metadata Updated] (file marked as "loaded" for 14 days)
REST API Flow (Internal or External Stage):

[Your Application/Script] --insertFiles API call--> [Snowpipe REST Endpoint]
|
v
[Snowpipe Service] --reads file--> [Stage] --COPY INTO--> [Target Table]
|
v
[Load Metadata Updated]

Key Architecture Points

  • Snowpipe uses a file queue - files are processed in order they arrive
  • Each file is loaded in its own micro-transaction
  • Snowflake provisions compute on-demand - no idle warehouse
  • Multiple pipes can read from the same stage
  • A pipe is bound to one COPY INTO statement

3. Complete Syntax Reference

CREATE PIPE

CREATE [ OR REPLACE ] PIPE [ IF NOT EXISTS ] <pipe_name>
  [ AUTO_INGEST = TRUE | FALSE ]        -- Enable event-driven loading
  [ ERROR_INTEGRATION = <name> ]        -- Send error notifications
  [ AWS_SNS_TOPIC = '<arn>' ]           -- For auto-ingest (AWS)
  [ INTEGRATION = '<name>' ]            -- Notification integration (Azure/GCS)
  [ COMMENT = '<string>' ]
  AS <copy_statement>                    -- The COPY INTO that defines the load

Example - Internal Stage (no auto-ingest):

CREATE PIPE my_pipe AS
COPY INTO my_table
FROM @my_internal_stage
FILE_FORMAT = (TYPE = 'CSV' SKIP_HEADER = 1)
ON_ERROR = 'SKIP_FILE';

Example - External Stage with Auto-Ingest (AWS):

CREATE PIPE my_pipe
  AUTO_INGEST = TRUE
  AS
  COPY INTO my_table
  FROM @my_s3_stage/path/
  FILE_FORMAT = my_csv_format
  ON_ERROR = 'CONTINUE';

Example - With ERROR_INTEGRATION:

CREATE PIPE my_pipe
  AUTO_INGEST = TRUE
  ERROR_INTEGRATION = my_error_notification
  AS
  COPY INTO my_table FROM @my_stage;

ALTER PIPE

-- Pause/Resume
ALTER PIPE <pipe_name> SET PIPE_EXECUTION_PAUSED = TRUE | FALSE;

-- Refresh (scan stage for new files)
ALTER PIPE <pipe_name> REFRESH
  [ PREFIX = '<path_prefix>' ]
  [ MODIFIED_AFTER = '<timestamp>' ];

-- Change properties
ALTER PIPE <pipe_name> SET
  PIPE_EXECUTION_PAUSED = TRUE
  COMMENT = 'Updated comment'
  ERROR_INTEGRATION = <name>;

DESCRIBE PIPE

DESCRIBE PIPE <pipe_name>;
-- Returns: created_on, name, database_name, schema_name, definition, owner,
--          notification_channel, comment, integration, pattern

SHOW PIPES

SHOW PIPES [ LIKE '<pattern>' ] [ IN SCHEMA <schema> ];

DROP PIPE

DROP PIPE [ IF EXISTS ] <pipe_name>;

SYSTEM$PIPE_STATUS

SELECT SYSTEM$PIPE_STATUS('<fully_qualified_pipe_name>');
-- Returns JSON:
-- {
--   "executionState": "RUNNING" | "PAUSED" | "STOPPED_FEATURE_DISABLED",
--   "pendingFileCount": 0,
--   "lastIngestedTimestamp": "2026-08-14T09:10:12.326Z",
--   "lastIngestedFilePath": "path/to/file.csv",
--   "notificationChannelName": "arn:aws:sqs:...",
--   "numOutstandingMessagesOnChannel": 0
-- }
Exam Trap - CREATE OR REPLACE: Running CREATE OR REPLACE PIPE on an existing pipe purges all load metadata. Files previously loaded WILL be loaded again, causing duplicates. Use ALTER PIPE instead when possible.

5. Auto-Ingest (Event-Driven Loading)

Auto-ingest enables Snowpipe to automatically detect and load new files as soon as they arrive in cloud storage.

Cloud-Specific Setup

CloudNotification MechanismSetup Steps
AWS S3 Event Notification → SQS Queue (Snowflake-managed) 1. Create external stage
2. Create pipe with AUTO_INGEST=TRUE
3. Note the notification_channel (SQS ARN)
4. Configure S3 bucket to send events to that SQS
Azure Event Grid → Storage Queue 1. Create notification integration
2. Create external stage
3. Create pipe with AUTO_INGEST=TRUE + INTEGRATION
4. Configure Event Grid subscription
GCP Pub/Sub Subscription 1. Create notification integration
2. Create external stage
3. Create pipe with AUTO_INGEST=TRUE + INTEGRATION
4. Configure GCS notification to Pub/Sub topic

AWS Auto-Ingest - Full Example

-- Step 1: Create storage integration
CREATE STORAGE INTEGRATION s3_integration
  TYPE = EXTERNAL_STAGE
  STORAGE_PROVIDER = 'S3'
  ENABLED = TRUE
  STORAGE_AWS_ROLE_ARN = 'arn:aws:iam::123456789012:role/snowflake-role'
  STORAGE_ALLOWED_LOCATIONS = ('s3://my-bucket/data/');

-- Step 2: Create external stage
CREATE STAGE my_s3_stage
  STORAGE_INTEGRATION = s3_integration
  URL = 's3://my-bucket/data/'
  FILE_FORMAT = (TYPE = 'JSON');

-- Step 3: Create pipe with auto-ingest
CREATE PIPE my_auto_pipe
  AUTO_INGEST = TRUE
  AS
  COPY INTO my_json_table
  FROM @my_s3_stage
  FILE_FORMAT = (TYPE = 'JSON');

-- Step 4: Get the SQS ARN to configure in AWS
SHOW PIPES LIKE 'MY_AUTO_PIPE';
-- Look at 'notification_channel' column = the SQS queue ARN
-- Configure S3 bucket events to send to this SQS
Key Point: The SQS queue is Snowflake-managed. You do NOT create it yourself. Snowflake creates and manages it. You only configure S3 to send events TO it.

6. REST API Loading (Programmatic)

When auto-ingest isn't suitable (internal stages, custom workflows), use the Snowpipe REST API.

REST API Endpoints

EndpointMethodPurpose
insertFilesPOSTSubmit file paths for loading
insertReportPOSTCheck status of submitted files
loadHistoryScanPOSTGet load history for a pipe

SDK Support

LanguageSDK
JavaSnowflake Ingest SDK (snowflake-ingest-sdk)
Pythonsnowflake-ingest library

Python Example (Conceptual)

from snowflake.ingest import SimpleIngestManager, StagedFile

# Create ingest manager
ingest_manager = SimpleIngestManager(
    account='myaccount',
    host='myaccount.snowflakecomputing.com',
    user='myuser',
    pipe='mydb.myschema.mypipe',
    private_key=private_key
)

# Submit files for ingestion
staged_files = [StagedFile('path/to/file1.csv', None)]
resp = ingest_manager.ingest_files(staged_files)

# Check status
history_resp = ingest_manager.get_history()

ALTER PIPE REFRESH (Manual Trigger)

-- Trigger pipe to scan stage (alternative to REST API)
ALTER PIPE my_pipe REFRESH;

-- Refresh only specific prefix
ALTER PIPE my_pipe REFRESH PREFIX = 'year=2026/month=08/';

-- Refresh only files modified after a timestamp
ALTER PIPE my_pipe REFRESH
  PREFIX = 'data/'
  MODIFIED_AFTER = '2026-08-14T00:00:00Z';
ALTER PIPE REFRESH is meant for backfill scenarios (loading files that arrived before the pipe was created or during downtime). For ongoing loading, use auto-ingest or REST API.

Transformations Supported in Snowpipe

Snowpipe supports limited transformations in the COPY INTO statement:

AllowedNot Allowed
Column reorderingJOINs
Column omission (skip columns)Aggregations (GROUP BY)
CAST / type conversionSubqueries
SUBSTR, TRIM on columnsWindow functions
$1, $2 positional referencesUDFs
Metadata columns (METADATA$FILENAME)FLATTEN
Simple expressionsComplex CTEs

Example - Loading with Transformations:

CREATE PIPE transformed_pipe AS
COPY INTO orders (order_id, customer, amount, load_file, load_time)
FROM (
  SELECT
    $1::INT,                          -- Column 1 cast to INT
    UPPER($2),                        -- Column 2 uppercase
    $4::DECIMAL(10,2),                -- Column 4 cast (skip col 3)
    METADATA$FILENAME,                -- Source filename
    METADATA$FILE_ROW_NUMBER          -- Row number in file
  FROM @my_stage
)
FILE_FORMAT = (TYPE='CSV' SKIP_HEADER=1);

11. Best Practices

File Size
  • Optimal: 100-250 MB compressed
  • Avoid tiny files (< 100 KB) - high per-file overhead
  • Avoid huge files (> 5 GB) - slow, blocks queue
  • If source produces small files, batch them upstream
Organization
  • Use meaningful path prefixes (date-partitioned)
  • One pipe per target table
  • Separate staging from production stages
  • Use ERROR_INTEGRATION for alerting
Monitoring
  • Check COPY_HISTORY regularly for failures
  • Monitor PIPE_USAGE_HISTORY for cost
  • Set up error notification integration
  • Use SYSTEM$PIPE_STATUS for real-time checks
Avoid Duplicates
  • NEVER use CREATE OR REPLACE on active pipes
  • Don't re-stage files with same name within 14 days
  • If you must recreate: pause, note last load, recreate, refresh with MODIFIED_AFTER
  • Consider adding METADATA$FILENAME to target table for audit
Top 5 Exam Traps:
  1. CREATE OR REPLACE = purges load history = duplicates
  2. PATTERN in Snowpipe = stage URL trimmed FIRST, then regex applied (different from COPY INTO)
  3. Auto-ingest NOT available for internal stages
  4. 14-day metadata = after 14 days, file can be reloaded
  5. Snowpipe does NOT use your warehouse = common wrong answer in cost questions
