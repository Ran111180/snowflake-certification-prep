1. Snowpipe Streaming (Row-Level Ingestion)

What is Snowpipe Streaming?

A row-level data ingestion API that writes data directly to Snowflake tables without requiring files or stages. Data is available for query within seconds.

AspectSnowpipe (File-Based)Snowpipe Streaming (Row-Based)
InputFiles on a stageRows via SDK (Java/Python)
Latency~1 minuteSeconds (sub-10 seconds)
Staging RequiredYes (files must be on stage)No (direct to table)
SDKSnowflake Ingest SDK (file paths)Snowflake Ingest SDK (insertRows)
ComputeSnowflake serverlessSnowflake serverless
Best ForFile-based pipelines (S3, Blob)Real-time IoT, clickstream, logs, CDC
OrderingNo guaranteed file orderOffset-based ordering within a channel
Exactly-Once14-day file dedupOffset token for exactly-once semantics
Channel ConceptN/AEach client opens a "channel" to a table

Snowpipe Streaming Architecture

[Your App / Kafka Connect / IoT Gateway]
| (insertRows API call via SDK)
v
[Snowpipe Streaming Service] --channel--> [Table Partition]
|
v
[Data available in seconds] + [Optimized into micro-partitions in background]

Key Concepts

  • Channel: A logical connection from one client to one table. Each channel has its own offset.
  • Offset Token: A string you provide with each insert. Used for exactly-once delivery and recovery.
  • insertRows: The API method that sends rows (as Map objects) directly to Snowflake.
  • No COPY INTO: Unlike file-based Snowpipe, there's no COPY statement or pipe object.

Java SDK Example (Conceptual)

// Open a channel
SnowflakeStreamingIngestChannel channel = client.openChannel(
    OpenChannelRequest.builder("MY_CHANNEL")
        .setDBName("MY_DB")
        .setSchemaName("MY_SCHEMA")
        .setTableName("MY_TABLE")
        .build()
);

// Insert rows
Map<String, Object> row = new HashMap<>();
row.put("id", 1001);
row.put("name", "Ranga");
row.put("event_time", "2026-08-14T09:30:00Z");

InsertValidationResponse resp = channel.insertRow(row, "offset_token_123");
// Data available in seconds!

4. RBAC & Privileges (Who Can Do What)

Key RBAC Concept: Owner's Rights

Pipes execute using the OWNER's privileges, not the caller's. This means:
  • The pipe owner's role must have INSERT on the target table
  • The pipe owner's role must have USAGE on the stage
  • If ownership is transferred, the new owner must also have these privileges
  • Even if another role triggers REFRESH, the load runs as the owner

Scenario: DATA_ENGINEER creates pipe, who else can interact?

RoleCan They...How to Grant
DATA_ENGINEER (owner) Everything: create, alter, refresh, drop, monitor Automatic (OWNERSHIP)
DATA_ANALYST View pipe status only GRANT MONITOR ON PIPE pipe_name TO ROLE DATA_ANALYST;
DATA_OPS Pause/Resume + Monitor GRANT OPERATE ON PIPE pipe_name TO ROLE DATA_OPS;
GRANT MONITOR ON PIPE pipe_name TO ROLE DATA_OPS;
SYSADMIN Transfer ownership GRANT OWNERSHIP ON PIPE pipe_name TO ROLE ANOTHER_ROLE;
ACCOUNTADMIN Everything (inherited) Automatic via hierarchy

Complete RBAC Setup for Production Pipe

-- As SECURITYADMIN: Create roles
CREATE ROLE IF NOT EXISTS PIPE_ADMIN;
CREATE ROLE IF NOT EXISTS PIPE_OPERATOR;
CREATE ROLE IF NOT EXISTS PIPE_VIEWER;

-- Grant hierarchy
GRANT ROLE PIPE_VIEWER TO ROLE PIPE_OPERATOR;
GRANT ROLE PIPE_OPERATOR TO ROLE PIPE_ADMIN;
GRANT ROLE PIPE_ADMIN TO ROLE SYSADMIN;

-- As pipe owner: Grant pipe privileges
GRANT MONITOR ON PIPE my_pipe TO ROLE PIPE_VIEWER;
GRANT OPERATE ON PIPE my_pipe TO ROLE PIPE_OPERATOR;
-- PIPE_ADMIN gets OWNERSHIP via transfer or inherits from SYSADMIN

-- Also need: stage and table access for the pipe OWNER
GRANT USAGE ON STAGE my_stage TO ROLE PIPE_ADMIN;
GRANT INSERT ON TABLE my_table TO ROLE PIPE_ADMIN;

5. Production Debugging Guide

Common Issues & Solutions

ProblemSymptomRoot CauseFix
Files not loading pendingFileCount = 0, no new data S3 event notification not configured or broken Verify S3 bucket events point to correct SQS ARN (from SHOW PIPES)
Pipe paused unexpectedly executionState = "PAUSED" Someone ran ALTER PIPE SET PAUSED=TRUE, or Snowflake auto-paused Resume: ALTER PIPE ... SET PIPE_EXECUTION_PAUSED=FALSE
Duplicate data Same rows appear multiple times CREATE OR REPLACE was used, purging load metadata Deduplicate with ROW_NUMBER(); prevent with ALTER PIPE instead
Load failed errors COPY_HISTORY shows "Load failed" Schema mismatch, bad data types, encoding issues Check FIRST_ERROR_MESSAGE; fix file or adjust FILE_FORMAT
Permission denied "Insufficient privileges" error Pipe owner lost INSERT on table or USAGE on stage Re-grant privileges to the pipe owner role
Files loaded but table empty COPY_HISTORY shows "Loaded" but 0 rows File has only headers, or PATTERN doesn't match Verify file content; check PATTERN regex
Stale data (files not detected) Files on stage but never loaded Files arrived before pipe was created (no notification) ALTER PIPE REFRESH PREFIX='...' MODIFIED_AFTER='...'
High pending file count pendingFileCount keeps growing Too many files arriving; compute backlog Reduce file frequency; increase file size; contact Snowflake support

Debug Queries

-- 1. Check pipe status
SELECT SYSTEM$PIPE_STATUS('db.schema.pipe_name');

-- 2. Check recent load history
SELECT * FROM TABLE(INFORMATION_SCHEMA.COPY_HISTORY(
  TABLE_NAME => 'MY_TABLE',
  START_TIME => DATEADD(HOURS, -24, CURRENT_TIMESTAMP())
)) ORDER BY LAST_LOAD_TIME DESC;

-- 3. Check for failed loads only
SELECT FILE_NAME, FIRST_ERROR_MESSAGE, LAST_LOAD_TIME
FROM TABLE(INFORMATION_SCHEMA.COPY_HISTORY(
  TABLE_NAME => 'MY_TABLE',
  START_TIME => DATEADD(DAYS, -7, CURRENT_TIMESTAMP())
)) WHERE STATUS = 'Load failed';

-- 4. Check pipe definition
DESCRIBE PIPE my_pipe;

-- 5. Check what's on the stage
LIST @my_stage;

-- 6. Validate errors from a specific load
SELECT * FROM TABLE(VALIDATE_PIPE_LOAD(
  PIPE_NAME => 'db.schema.pipe_name',
  START_TIME => DATEADD(HOURS, -1, CURRENT_TIMESTAMP())
));

6. Optimizing Slow Pipelines

Why Your Pipeline is Slow

CauseDiagnosisSolution
Files too small (< 100 KB) High file count, low bytes per file in PIPE_USAGE_HISTORY Batch small records into larger files upstream (100-250 MB target)
Files too large (> 1 GB) Long processing time per file; queue backs up Split files into 100-250 MB chunks before staging
Too many pipes on same table Lock contention, slower inserts Consolidate to fewer pipes; use path prefixes to partition
Complex COPY transformations Slower than simple column mapping Load raw first, transform with tasks/streams after
Notification delays Gap between file arrival and pendingFileCount increase Check cloud notification config; ensure no SQS throttling
Burst of files pendingFileCount spikes, gradual drain Normal behavior; Snowpipe scales up but not instantaneously
JSON/Avro parsing overhead Slower loads for semi-structured vs CSV Use STRIP_OUTER_ARRAY, STRIP_NULL_VALUES to reduce parse cost

Optimization Checklist

  • File size: 100-250 MB compressed (gzip/snappy)
  • File format: Parquet/Avro for complex data; CSV for simple tabular
  • Compression: Always compress (gzip for CSV, snappy for Parquet)
  • Partitioning: Use date-based prefixes (year=2026/month=08/day=14/)
  • One pipe per table (avoid multiple pipes inserting into same table)
  • Monitor PIPE_USAGE_HISTORY weekly for anomalies
  • Use ERROR_INTEGRATION for immediate alerting

Monitoring Cost

-- Credit usage by pipe (Account Usage - 365 days, 1-2hr lag)
SELECT
  PIPE_NAME,
  SUM(CREDITS_USED) as total_credits,
  SUM(FILES_INSERTED) as total_files,
  SUM(BYTES_INSERTED) as total_bytes
FROM SNOWFLAKE.ACCOUNT_USAGE.PIPE_USAGE_HISTORY
WHERE START_TIME >= DATEADD(DAYS, -30, CURRENT_TIMESTAMP())
GROUP BY PIPE_NAME
ORDER BY total_credits DESC;

-- Real-time credit check (Information Schema - 14 days)
SELECT *
FROM TABLE(INFORMATION_SCHEMA.PIPE_USAGE_HISTORY(
  DATE_RANGE_START => DATEADD(DAYS, -7, CURRENT_TIMESTAMP()),
  PIPE_NAME => 'my_db.my_schema.my_pipe'
));

8. Error Handling Deep Dive

ON_ERROR Options

OptionBehaviorUse When
SKIP_FILE Entire file skipped if ANY row has error Data quality is critical; prefer no partial loads
SKIP_FILE_<n> Skip file if error count exceeds n Tolerate a few bad rows per file
SKIP_FILE_<n>% Skip file if error percentage exceeds n% Percentage-based tolerance
CONTINUE Load valid rows, skip only bad rows Maximize data loaded; accept some data loss
ABORT_STATEMENT Abort entire load on first error (default for COPY INTO, NOT for Snowpipe) Rarely used with Snowpipe

ERROR_INTEGRATION (Automated Alerting)

-- Create error notification integration
CREATE NOTIFICATION INTEGRATION pipe_error_notify
  TYPE = QUEUE
  ENABLED = TRUE
  NOTIFICATION_PROVIDER = AWS_SNS
  DIRECTION = OUTBOUND
  AWS_SNS_TOPIC_ARN = 'arn:aws:sns:us-east-1:123456:pipe-errors'
  AWS_SNS_ROLE_ARN = 'arn:aws:iam::123456:role/sns-role';

-- Use in pipe
CREATE PIPE my_pipe
  AUTO_INGEST = TRUE
  ERROR_INTEGRATION = pipe_error_notify
  AS COPY INTO my_table FROM @my_stage;
