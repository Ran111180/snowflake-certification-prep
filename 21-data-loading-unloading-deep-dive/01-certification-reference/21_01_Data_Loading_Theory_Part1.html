1. Stages - Where Data Lives Before/After Loading

Stage Types Overview

A stage is a location (internal or external) where data files are stored before loading into Snowflake tables or after unloading from them.

Stage TypeReferenceDescriptionScope
User Stage@~Allocated to each user automaticallyOnly that user can access
Table Stage@%table_nameAllocated to each table automaticallyAny user with table privileges
Named Internal Stage@stage_nameExplicitly created database objectControlled by RBAC grants
External Stage (S3)@ext_stagePoints to AWS S3 bucketRequires storage integration or credentials
External Stage (Azure)@ext_stagePoints to Azure Blob/ADLSRequires storage integration or SAS token
External Stage (GCS)@ext_stagePoints to Google Cloud StorageRequires storage integration

Internal Stage Details

User Stage (@~)
  • Cannot be altered or dropped
  • Cannot set file format on it
  • Cannot be shared with other users
  • Each user gets one automatically
  • Data encrypted with 128-bit key
  • PUT uploads here by default
-- Reference user stage
PUT file://data.csv @~;
LIST @~;
Table Stage (@%table)
  • Cannot be altered or dropped
  • Cannot set file format on it
  • One per table, auto-created
  • Multiple users can access (with table privs)
  • Cannot GRANT directly on table stages
  • Files only loadable into THAT table
-- Reference table stage
PUT file://data.csv @%my_table;
LIST @%my_table;
Named Internal Stage (CREATE STAGE)
  • Explicitly created as a database object
  • Can specify file format, encryption, directory table
  • Can be granted to roles (USAGE privilege)
  • Most flexible - recommended for production
  • Supports directory tables (for listing files as queryable table)
CREATE OR REPLACE STAGE my_stage
  FILE_FORMAT = (TYPE = CSV FIELD_DELIMITER = '|')
  ENCRYPTION = (TYPE = 'SNOWFLAKE_SSE')
  DIRECTORY = (ENABLE = TRUE)
  COMMENT = 'Production loading stage';

External Stage Details

External Stage Creation
-- AWS S3 with Storage Integration (recommended)
CREATE OR REPLACE STAGE s3_stage
  STORAGE_INTEGRATION = my_s3_integration
  URL = 's3://my-bucket/path/'
  FILE_FORMAT = (TYPE = PARQUET);

-- Azure Blob with Storage Integration
CREATE OR REPLACE STAGE azure_stage
  STORAGE_INTEGRATION = my_azure_integration
  URL = 'azure://myaccount.blob.core.windows.net/container/path/'
  FILE_FORMAT = (TYPE = JSON);

-- GCS with Storage Integration
CREATE OR REPLACE STAGE gcs_stage
  STORAGE_INTEGRATION = my_gcs_integration
  URL = 'gcs://my-bucket/path/'
  FILE_FORMAT = (TYPE = CSV);
Exam Tip: User stages and table stages CANNOT have file formats assigned to them. You must specify FILE_FORMAT in the COPY INTO command. Only named stages (internal or external) can have a default file format.

2. FILE FORMAT Object

CREATE FILE FORMAT Syntax
CREATE OR REPLACE FILE FORMAT my_csv_format
  TYPE = CSV
  FIELD_DELIMITER = ','
  RECORD_DELIMITER = '\n'
  SKIP_HEADER = 1
  FIELD_OPTIONALLY_ENCLOSED_BY = '"'
  NULL_IF = ('NULL', 'null', '')
  EMPTY_FIELD_AS_NULL = TRUE
  COMPRESSION = AUTO;
TYPEKey OptionsUse Case
CSVFIELD_DELIMITER, RECORD_DELIMITER, SKIP_HEADER, FIELD_OPTIONALLY_ENCLOSED_BY, NULL_IF, ESCAPE, ESCAPE_UNENCLOSED_FIELD, DATE_FORMAT, TIME_FORMAT, TIMESTAMP_FORMATStructured flat files, exports from RDBMS
JSONSTRIP_OUTER_ARRAY, STRIP_NULL_VALUES, ALLOW_DUPLICATE, ENABLE_OCTAL, IGNORE_UTF8_ERRORSSemi-structured nested data
PARQUETCOMPRESSION (SNAPPY/LZO/NONE), BINARY_AS_TEXT, TRIM_SPACEColumnar analytics, efficient storage
AVROCOMPRESSION (AUTO/DEFLATE/SNAPPY/NONE), TRIM_SPACESchema-evolution-friendly, Kafka data
ORCTRIM_SPACE, NULL_IFHadoop ecosystem, columnar format
XMLSTRIP_OUTER_ELEMENT, DISABLE_SNOWFLAKE_DATA, DISABLE_AUTO_CONVERT, PRESERVE_SPACELegacy systems, SOAP integrations
Key Point: FILE FORMAT objects are schema-level database objects. They can be reused across multiple COPY commands and stages. They follow standard RBAC (USAGE grant required).

3. COPY INTO <table> - Full Syntax

Complete COPY INTO Syntax
COPY INTO [database.]schema.table_name
  FROM { @stage_name | @~ | @%table_name | 's3://bucket/path' }
  [ FILES = ('file1.csv', 'file2.csv') ]
  [ PATTERN = '.*sales.*[.]csv' ]
  [ FILE_FORMAT = ( FORMAT_NAME = my_format | TYPE = CSV ... ) ]
  [ ON_ERROR = { ABORT_STATEMENT | CONTINUE | SKIP_FILE | SKIP_FILE_num% } ]
  [ SIZE_LIMIT = num_bytes ]
  [ PURGE = TRUE | FALSE ]
  [ FORCE = TRUE | FALSE ]
  [ VALIDATION_MODE = RETURN_n_ROWS | RETURN_ERRORS | RETURN_ALL_ERRORS ]
  [ MATCH_BY_COLUMN_NAME = CASE_INSENSITIVE | CASE_SENSITIVE | NONE ]
  [ RETURN_FAILED_ONLY = TRUE | FALSE ]
  [ ENFORCE_LENGTH = TRUE | FALSE ]
  [ TRUNCATECOLUMNS = TRUE | FALSE ]
  [ LOAD_UNCERTAIN_FILES = TRUE | FALSE ];

Key COPY INTO Options

OptionDefaultDescription
FILESAll filesExplicit list of file names to load (max 1000)
PATTERNNoneRegex pattern to filter files by name

4. PUT Command - Upload Local Files to Internal Stage

PUT Syntax
PUT file://path/to/local/file.csv @stage_name
  [ /path/prefix ]
  [ PARALLEL = num_threads ]
  [ AUTO_COMPRESS = TRUE | FALSE ]
  [ SOURCE_COMPRESSION = AUTO_DETECT | GZIP | BZ2 | BROTLI | ZSTD | DEFLATE | RAW_DEFLATE | NONE ]
  [ OVERWRITE = TRUE | FALSE ];
  • PARALLEL - Number of threads for upload (default 4, max 99)
  • AUTO_COMPRESS - Automatically gzip files before upload (default TRUE)
  • OVERWRITE - Overwrite existing files in stage (default FALSE)
  • Works ONLY with internal stages (not external)
  • Can only be run from SnowSQL, JDBC/ODBC drivers, Python connector (NOT from Snowsight UI)
Exam Trap: PUT only works with internal stages. You cannot PUT files to an external stage (S3/Azure/GCS). For external stages, upload files using the cloud provider's tools (aws s3 cp, azcopy, gsutil).

5. LIST and REMOVE Commands

LIST (LS) Command
-- List all files in a stage
LIST @my_stage;
LS @my_stage;

-- List with pattern filter
LIST @my_stage PATTERN = '.*[.]csv';

-- List user stage
LIST @~;

-- List table stage
LIST @%my_table;

Returns: name, size, md5, last_modified

REMOVE (RM) Command
-- Remove specific file
REMOVE @my_stage/data.csv.gz;
RM @my_stage/data.csv.gz;

-- Remove all files with pattern
REMOVE @my_stage PATTERN = '.*[.]csv[.]gz';

-- Remove from user stage
REMOVE @~/data.csv.gz;

Only works on internal stages. For external, use cloud tools.

6. File Sizing Best Practices

Optimal File Sizes for Loading
AspectRecommendationReason
Optimal compressed size100-250 MBAllows parallel loading across warehouse nodes
Minimum practical size10 MB+Below this, overhead of file management dominates
Maximum practical size~5 GBLarger files reduce parallelism (one file = one thread)
Number of filesMultiple of cluster nodesEach file can be loaded by a separate thread/node
Splitting strategySplit large files before upload100 x 100MB files load faster than 1 x 10GB file
Key Exam Fact: Snowflake recommends files be 100-250 MB compressed for optimal parallel loading. Each file is assigned to a single compute node, so many appropriately-sized files maximize parallelism across warehouse nodes.

7. ON_ERROR Options

ON_ERROR Behavior Comparison
OptionBehaviorUse Case
ABORT_STATEMENTAbort entire COPY. No data loaded from any file. (DEFAULT for bulk COPY)All-or-nothing loads where data quality is critical
CONTINUESkip error rows, continue loading remaining rows from all filesTolerant loads where some bad rows are acceptable
SKIP_FILESkip entire file if ANY error found, continue with other filesFile-level atomicity; DEFAULT for Snowpipe
SKIP_FILE_numSkip file if error count >= num (e.g., SKIP_FILE_5)Allow a few errors per file, skip if too many
SKIP_FILE_num%Skip file if error percentage >= num% (e.g., SKIP_FILE_10%)Proportional tolerance; skip if >10% of rows fail
Important Distinction: Default ON_ERROR for manual COPY INTO is ABORT_STATEMENT. Default ON_ERROR for Snowpipe is SKIP_FILE. This is frequently tested.

8. Features (15)

Data Loading Features
  1. Multiple file format support - CSV, JSON, Parquet, Avro, ORC, XML natively
  2. Automatic compression detection - gzip, bz2, brotli, zstd auto-detected
  3. Parallel loading - Multiple files loaded simultaneously across warehouse nodes
  4. Transformation during load - SELECT expressions, column reordering, type casting in COPY
  5. Load history tracking - 64-day metadata prevents duplicate file loads
  6. PURGE option - Auto-delete files from stage after successful load
  7. VALIDATION_MODE - Dry-run validation without actually loading data
  8. MATCH_BY_COLUMN_NAME - Match by header names instead of positional order
  9. SIZE_LIMIT - Cap the total volume loaded in a single COPY command
  10. FILE_FORMAT reusability - Named format objects shareable across COPY commands
  11. Directory tables - Query file metadata as a virtual table on stages
  12. Storage integrations - Secure, credential-free access to cloud storage
  13. COPY_HISTORY function - Programmatic access to load metadata
  14. PATTERN-based file selection - Filter files by regex during COPY
  15. Error handling flexibility - ABORT, CONTINUE, SKIP_FILE with thresholds

9. Limitations (15)

Data Loading Limitations
  1. PUT only for internal stages - Cannot PUT files directly to S3/Azure/GCS
  2. PUT not from Snowsight UI - Requires SnowSQL or connector (JDBC/ODBC/Python)
  3. User/table stages cannot set file format - Must specify in COPY command
  4. User/table stages cannot be granted - No RBAC granularity on implicit stages
  5. 64-day history prevents re-load - Same file (name+checksum) skipped for 64 days unless FORCE=TRUE
  6. FILES option max 1000 files - Cannot specify more than 1000 files in a single COPY
  7. COPY transformation limited - No JOINs, subqueries, or aggregate functions
  8. METADATA$ only during COPY - METADATA$FILENAME etc. not available in regular queries
  9. VALIDATION_MODE doesn't load - Cannot validate AND load in same command
  10. One warehouse thread per file - A single file cannot be split across threads during load
  11. COPY INTO is not a DML statement - Does not generate stream change records
  12. External stage credentials - Must configure storage integration or embed credentials
  13. No recursive directory traversal by default - Must configure or include path patterns
  14. PATTERN uses regex - SQL LIKE patterns (% and _) do NOT work; uses Java regex syntax
  15. COPY timeout - Very large loads may hit statement timeout limits; use SIZE_LIMIT to batch
Common Exam Trap: COPY INTO does NOT generate change data capture records for streams. If you need a stream on a table, be aware that COPY INTO populates it, but COPY itself is treated as a special DML that DOES populate streams (INSERT-only). The limitation is that it cannot be used in stream-based transactional patterns like MERGE.
