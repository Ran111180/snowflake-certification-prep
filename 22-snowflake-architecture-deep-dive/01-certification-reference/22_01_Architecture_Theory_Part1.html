22.01 Snowflake Architecture - Fundamentals

Three-layer architecture, SaaS model, storage, compute, cloud services, editions

1. Snowflake SaaS Model

Key Characteristics

  • True SaaS - No hardware to provision, no software to install, no infrastructure to manage
  • Multi-tenant - Shared infrastructure with complete data isolation
  • Pay-per-use - Billed for storage (per TB/month) and compute (per credit/second)
  • Zero maintenance - Automatic upgrades, patches, and tuning
  • Near-zero administration - No indexes, no partitioning keys, no vacuuming, no tuning knobs
Exam Tip: Snowflake is NOT a "hosted" version of existing software. It was built from scratch for the cloud, using a new SQL query engine (not based on Hadoop, Postgres, or any existing system).

3. Storage Layer

Micro-Partitions

PropertyDetail
Size50-500 MB of uncompressed data per micro-partition
FormatColumnar (each column stored independently)
CompressionAutomatic, column-specific compression algorithms
ImmutabilityOnce written, never modified (copy-on-write for updates)
OrganizationData stored in natural ingestion order (no explicit partitioning key)
MetadataMin/max per column, distinct count, null count stored separately
Key Point: Snowflake automatically organizes data into micro-partitions. Users do NOT define partitioning keys (unlike Hive/Spark). Clustering keys can optionally be defined to influence ordering.

Storage Characteristics

  • Data stored in the cloud provider's blob storage (S3, Azure Blob, GCS)
  • Managed entirely by Snowflake - users cannot directly access underlying files
  • Compressed typically 4-5x (varies by data type)
  • Billed monthly based on average compressed storage used
  • Supports structured (relational) and semi-structured (JSON, Avro, Parquet, ORC, XML)

Key Compute Properties

  • Independent scaling - Each warehouse scales independently without affecting others
  • No resource contention - Warehouses do NOT share compute resources
  • Local SSD cache - Each warehouse has local disk cache for recently accessed data
  • Auto-suspend - Configurable idle timeout (default 10 minutes, minimum 1 minute or "never")
  • Auto-resume - Automatically starts when a query is submitted
  • Per-second billing - Minimum 60 seconds, then billed per-second
  • Instant resize - Can scale up/down without restarting running queries
Exam Alert: Multi-cluster warehouses are Enterprise Edition and above only. They scale OUT (add clusters), not UP (add nodes to existing cluster).

5. Cloud Services Layer

Responsibilities

Query Processing

  • Query parsing and optimization
  • Query compilation (into execution plan)
  • Metadata management
  • Statistics collection
  • Result caching

Infrastructure

  • Authentication and access control
  • Security (encryption, network policies)
  • Transaction management (ACID)
  • Infrastructure management
  • Metadata storage
Billing: Cloud Services are billed only when usage exceeds 10% of total daily compute credits. The first 10% is free (adjustment applied daily).

8. Key Features (15)

  1. Separation of storage and compute
  2. Near-unlimited, independent scaling
  3. Zero-copy cloning
  4. Time Travel (up to 90 days)
  5. Fail-safe (7-day recovery)
  6. Automatic encryption (at rest and in transit)
  7. Semi-structured data support (VARIANT)
  8. Secure data sharing (no data movement)
  9. Multi-cluster warehouses (auto-scale)
  10. Materialized views (auto-maintained)
  11. Result caching (24 hours)
  12. Automatic micro-partitioning
  13. Native support for JSON, Avro, Parquet, ORC, XML
  14. Continuous data protection (no backups needed)
  15. Cross-cloud/cross-region replication

9. Key Limitations (15)

  1. No user-defined indexes (relies on micro-partition pruning)
  2. No direct access to underlying storage files
  3. Account locked to one cloud/region (replication needed for multi-region)
  4. No support for stored procedures in all languages equally (SQL, JavaScript, Python, Java, Scala)
  5. Limited UDF execution time (statements can time out)
  6. No in-place updates (copy-on-write model)
  7. Result cache limited to 24 hours and exact query match
  8. Multi-cluster warehouses require Enterprise Edition or higher
  9. Time Travel beyond 1 day requires Enterprise Edition
  10. No support for arbitrary binary data types as partition keys
  11. VARIANT column size limit of 16 MB per value
  12. Maximum row size of 16 MB (compressed)
  13. Cannot run on-premises (cloud only)
  14. No column-level encryption (encryption is storage-level)
  15. Network policies limited to IP-based rules (no FQDN filtering)
