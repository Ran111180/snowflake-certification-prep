What is Snowflake Cortex

Overview

Snowflake Cortex is a fully managed AI/ML service that brings large language models (LLMs) and ML capabilities directly into the Snowflake Data Cloud platform.

  • Managed service - No infrastructure provisioning, no GPU management, no model deployment
  • SQL interface - All AI functions callable via standard SQL (SELECT statements)
  • Data governance - Data never leaves Snowflake; same RBAC and security apply
  • Pay-per-use - Credit-based billing per token processed
  • Serverless - Automatically scales, no warehouse needed for most functions
Key Architecture Points:
  • Cortex runs within Snowflake's secure infrastructure
  • No data movement outside Snowflake boundary
  • Functions are invoked as SQL functions in queries
  • Results returned as standard SQL column values
  • Supports both batch (table operations) and real-time (single-row) inference
Cortex AI functions are serverless - they do NOT require a virtual warehouse for execution (though some services like Cortex Search require a warehouse for building the index).

LLM Functions

AI_COMPLETE - Text Generation

The most versatile Cortex function - generates text responses using specified LLM models.

-- Simple completion
SELECT SNOWFLAKE.CORTEX.AI_COMPLETE('mistral-large2', 'Explain Snowflake data sharing');

-- With options
SELECT SNOWFLAKE.CORTEX.AI_COMPLETE(
  'mistral-large2',
  'Summarize this text: ' || my_column,
  {'temperature': 0.3, 'max_tokens': 500}
) FROM my_table;

Key parameters:

  • model - Required. The LLM model name (string)
  • prompt - Required. The text prompt or message array
  • options - Optional OBJECT with temperature, max_tokens, top_p

AI_SENTIMENT - Sentiment Analysis

Returns a sentiment score between -1 (most negative) and +1 (most positive).

SELECT SNOWFLAKE.CORTEX.AI_SENTIMENT('Great product, love it!') AS score;
-- Returns: 0.85 (positive)

SELECT SNOWFLAKE.CORTEX.AI_SENTIMENT('Terrible experience, never again') AS score;
-- Returns: -0.92 (negative)
  • Returns a FLOAT value between -1 and 1
  • No model selection needed (uses built-in model)
  • 0 = neutral, positive = positive sentiment, negative = negative sentiment
AI_SENTIMENT returns a numeric score (-1 to 1), NOT a label like "positive" or "negative". You must interpret the number yourself.

AI_SUMMARIZE - Text Summarization

SELECT SNOWFLAKE.CORTEX.AI_SUMMARIZE(long_text_column) FROM articles;
  • Takes a single text input
  • Returns a concise summary of the input text
  • No model selection required
  • Useful for document processing pipelines

AI_TRANSLATE - Language Translation

SELECT SNOWFLAKE.CORTEX.AI_TRANSLATE(
  text_column,
  'en',   -- source language
  'fr'    -- target language
) FROM documents;
  • Parameters: text, source_language, target_language
  • Uses ISO 639-1 language codes (en, fr, de, es, ja, etc.)
  • Source language can be empty string '' for auto-detect

AI_CLASSIFY - Text Classification

SELECT SNOWFLAKE.CORTEX.AI_CLASSIFY(
  'I need to return this product',
  ['Complaint', 'Inquiry', 'Return Request', 'Compliment']
) AS category;
  • Classifies text into one of the provided categories
  • Second argument is an ARRAY of category labels
  • Returns an OBJECT with the chosen label and confidence score

AI_EXTRACT - Structured Extraction

SELECT SNOWFLAKE.CORTEX.AI_EXTRACT(
  'John Smith ordered 3 widgets on Jan 15, 2024 for $99.99',
  ['customer_name', 'quantity', 'order_date', 'total_price']
) AS extracted;
  • Extracts structured data from unstructured text
  • Second argument is an ARRAY of field names to extract
  • Returns an OBJECT with key-value pairs

Text Embedding & Vector Search

AI_EMBED_TEXT - Vector Generation

-- Generate embedding vector
SELECT SNOWFLAKE.CORTEX.AI_EMBED_TEXT(
  'snowflake-arctic-embed-m-v1.5',
  'Snowflake is a cloud data platform'
) AS embedding;

-- Store embeddings in a table
CREATE TABLE document_embeddings AS
SELECT
  doc_id,
  doc_text,
  SNOWFLAKE.CORTEX.AI_EMBED_TEXT('snowflake-arctic-embed-m-v1.5', doc_text) AS embedding
FROM documents;
  • Converts text into a dense vector (array of floats)
  • Vectors capture semantic meaning of text
  • Similar texts produce similar vectors
  • Model selection required (determines vector dimensions)
  • Returns a VECTOR data type

Vector Similarity Functions

FunctionDescriptionRangeBest Match
VECTOR_COSINE_SIMILARITY(a, b)Cosine similarity between two vectors-1 to 1Highest value (1)
VECTOR_L2_DISTANCE(a, b)Euclidean distance between two vectors0 to infinityLowest value (0)
VECTOR_INNER_PRODUCT(a, b)Dot product of two vectorsVariesHighest value
 
-- Semantic search example
SELECT doc_id, doc_text,
  VECTOR_COSINE_SIMILARITY(
    embedding,
    SNOWFLAKE.CORTEX.AI_EMBED_TEXT('snowflake-arctic-embed-m-v1.5', 'How do I share data?')
  ) AS similarity
FROM document_embeddings
ORDER BY similarity DESC
LIMIT 5;
VECTOR_COSINE_SIMILARITY returns values between -1 and 1, where 1 = identical. VECTOR_L2_DISTANCE returns 0+ where 0 = identical. They rank in OPPOSITE directions.

Cortex Search Service

Overview

Cortex Search Service provides hybrid search combining semantic understanding with keyword matching.

  • Hybrid search - Combines semantic (vector) search with keyword (BM25) search
  • Managed service - Snowflake handles indexing, retrieval, and ranking
  • Auto-refresh - Index stays updated based on TARGET_LAG setting
  • No embedding management - Embeddings created and managed automatically

CREATE CORTEX SEARCH SERVICE Syntax

CREATE OR REPLACE CORTEX SEARCH SERVICE my_search_service
  ON search_column
  ATTRIBUTES category, author     -- filterable columns
  WAREHOUSE = my_wh
  TARGET_LAG = '1 hour'
  AS (
    SELECT
      search_column,
      category,
      author,
      doc_id
    FROM my_documents_table
  );

Key components:

  • ON - The text column to search over
  • ATTRIBUTES - Additional columns for filtering results
  • WAREHOUSE - Warehouse for building/refreshing the index
  • TARGET_LAG - How fresh the index should be (e.g., '1 minute', '1 hour')
  • AS (query) - Source query defining the searchable data

Querying Cortex Search (via SEARCH function)

-- Search with the SEARCH function
SELECT PARSE_JSON(
  SNOWFLAKE.CORTEX.SEARCH(
    'my_search_service',    -- service name
    '{
      "query": "How to set up data sharing",
      "columns": ["search_column", "category", "doc_id"],
      "limit": 5
    }'
  )
);

Cortex Analyst

Overview

Cortex Analyst converts natural language questions into SQL queries against your data.

  • Requires a semantic view (formerly semantic model) describing your data
  • Users ask questions in plain English
  • Cortex Analyst generates and executes SQL
  • Returns results in structured format
  • Supports verified queries for accuracy

Semantic View

A YAML-based definition that describes your data in business terms:

-- Semantic views define:
-- - Tables and their relationships (joins)
-- - Dimensions (categorical fields)
-- - Measures/Metrics (aggregatable fields)
-- - Time dimensions
-- - Verified queries (known-good Q&A pairs)

-- Created as a Snowflake object:
CREATE OR REPLACE SEMANTIC VIEW my_semantic_view
  AS VIEW_DEFINITION;
  • Maps business terminology to physical tables/columns
  • Defines relationships between tables
  • Specifies metrics, dimensions, and time grains
  • Verified queries improve accuracy for common questions
Cortex Analyst requires a semantic view - it cannot generate SQL without one. The semantic view tells it which tables, columns, and joins to use.

Features & Limitations

15 Key Features

  1. SQL-native interface - All functions called via standard SQL
  2. No infrastructure management - Fully serverless AI inference
  3. Data stays in Snowflake - No data movement to external services
  4. Multiple LLM providers - Access Meta, Mistral, Anthropic, AI21 models
  5. Batch processing - Run AI functions over entire tables efficiently
  6. Built-in embeddings - Native vector generation with Arctic models
  7. Hybrid search - Cortex Search combines semantic + keyword search
  8. Natural language analytics - Cortex Analyst for text-to-SQL
  9. Fine-tuning support - Customize models on your data
  10. Document AI - Parse and extract from PDFs and documents
  11. Built-in ML - FORECAST, ANOMALY_DETECTION, CLASSIFICATION without code
  12. RBAC integration - Standard Snowflake access control applies
  13. Vector data type - Native vector storage and similarity operations
  14. Auto-scaling - Handles varying workloads automatically
  15. Multi-turn chat - AI_COMPLETE supports conversation history via message arrays

15 Key Limitations

  1. Region availability - Not all models available in all Snowflake regions
  2. Token limits - Each model has maximum context window (input + output)
  3. Rate limits - Per-account throttling on concurrent requests
  4. Cost per token - Large-scale batch processing can be expensive
  5. No real-time streaming - Results returned only after full generation
  6. Cortex Analyst requires semantic view - Cannot work without data model definition
  7. Embedding dimension fixed per model - Cannot change vector size after generation
  8. Cortex Search TARGET_LAG - Index not real-time; minimum lag applies
  9. No custom model hosting - Can only use Snowflake-provided models (except fine-tuning)
  10. Fine-tuning limited models - Only specific base models support fine-tuning
  11. FORECAST minimum data - Requires minimum number of historical data points
  12. Output non-deterministic - Same prompt can produce different outputs (unless temperature=0)
  13. No image generation - Cortex is text-in/text-out (except Document AI for parsing)
  14. Cortex Search max document size - Documents have size limits for indexing
  15. Network isolation - Cannot call external APIs or URLs from within Cortex functions
For the exam, remember: Cortex functions are SERVERLESS (no warehouse needed for LLM functions), data NEVER leaves Snowflake, and all functions are called via SQL. Cortex Search DOES need a warehouse for index building.
