AI_COMPLETE - Advanced Usage

System Prompts & Temperature

-- Using system prompt with options
SELECT SNOWFLAKE.CORTEX.AI_COMPLETE(
  'mistral-large2',
  [
    {'role': 'system', 'content': 'You are a helpful data analyst. Be concise.'},
    {'role': 'user', 'content': 'What is a materialized view?'}
  ],
  {
    'temperature': 0.2,    -- 0=deterministic, 1=creative
    'max_tokens': 500,     -- maximum output length
    'top_p': 0.9           -- nucleus sampling
  }
);
OptionTypeRangeDescription
temperatureFLOAT0 to 1Controls randomness. 0 = deterministic, 1 = most creative
max_tokensINTEGER1 to model maxMaximum number of tokens in the response
top_pFLOAT0 to 1Nucleus sampling - considers tokens with cumulative probability ≤ top_p

Multi-Turn Chat (Message Array)

AI_COMPLETE supports conversation history via an ARRAY of message objects:

SELECT SNOWFLAKE.CORTEX.AI_COMPLETE(
  'mistral-large2',
  [
    {'role': 'system', 'content': 'You are a Snowflake expert.'},
    {'role': 'user', 'content': 'What is a virtual warehouse?'},
    {'role': 'assistant', 'content': 'A virtual warehouse is a cluster of compute...'},
    {'role': 'user', 'content': 'How do I resize one?'}
  ]
);

Message roles:

  • system - Sets behavior/persona (optional, at most one, first message)
  • user - The human/user messages
  • assistant - Previous AI responses (for context)

Structured Output

-- Request JSON output via prompt engineering
SELECT PARSE_JSON(
  SNOWFLAKE.CORTEX.AI_COMPLETE(
    'mistral-large2',
    'Extract the following as JSON with keys name, age, city: 
     "John is 30 years old and lives in Seattle"'
  )
) AS structured_result;
  • Use prompt engineering to request structured (JSON) output
  • Wrap result with PARSE_JSON for further processing
  • System prompt can enforce output format
When AI_COMPLETE receives an ARRAY (messages), it operates in chat mode. When it receives a VARCHAR (single string), it operates in simple completion mode. Both are valid.

Document AI

AI_PARSE_DOCUMENT

Extracts text content from documents (PDFs, images) using OCR and text extraction.

-- Parse a PDF from a stage
SELECT SNOWFLAKE.CORTEX.AI_PARSE_DOCUMENT(
  '@my_stage',           -- stage reference
  'reports/q4_report.pdf',  -- relative path in stage
  {'mode': 'layout'}    -- options: 'layout' or 'ocr'
);

-- Parse with OCR mode for scanned documents
SELECT SNOWFLAKE.CORTEX.AI_PARSE_DOCUMENT(
  '@my_stage',
  'scanned_invoice.png',
  {'mode': 'ocr'}
);
  • layout mode - For digital PDFs with selectable text (faster)
  • ocr mode - For scanned documents/images (uses OCR)
  • Returns structured text content from the document
  • Supports PDF, PNG, JPEG, TIFF formats

AI_EXTRACT for Documents

-- Extract structured fields from parsed document text
SELECT SNOWFLAKE.CORTEX.AI_EXTRACT(
  parsed_text,
  ['invoice_number', 'total_amount', 'vendor_name', 'due_date']
) FROM parsed_documents;

Combine AI_PARSE_DOCUMENT + AI_EXTRACT for end-to-end document processing pipeline.

Cortex Fine-Tuning

Overview

Fine-tune supported base models on your custom data to improve task-specific performance.

-- Create a fine-tuning job
SELECT SNOWFLAKE.CORTEX.FINETUNE(
  'CREATE',
  'mistral-7b',                    -- base model
  '@my_stage/training_data.jsonl', -- training data
  '@my_stage/validation_data.jsonl', -- validation data (optional)
  'my_custom_model'                -- output model name
);

-- Check fine-tuning job status
SELECT SNOWFLAKE.CORTEX.FINETUNE('DESCRIBE', 'job_id_here');

-- Use the fine-tuned model
SELECT SNOWFLAKE.CORTEX.AI_COMPLETE('my_custom_model', 'Your prompt here');

Training Data Format (JSONL)

{"messages": [{"role": "system", "content": "You are a classifier."}, {"role": "user", "content": "Classify: Server is down"}, {"role": "assistant", "content": "Critical"}]}
{"messages": [{"role": "system", "content": "You are a classifier."}, {"role": "user", "content": "Classify: Button color wrong"}, {"role": "assistant", "content": "Low"}]}
  • JSONL format (one JSON object per line)
  • Each line contains a messages array with role/content pairs
  • Minimum training examples required (varies by model)
  • Consistent system prompt recommended across examples
Fine-tuning training data must be in JSONL format with a "messages" array. The data must be stored on a Snowflake stage. Not all models support fine-tuning.

Cortex Search Service - Deep Dive

Full CREATE Syntax

CREATE OR REPLACE CORTEX SEARCH SERVICE db.schema.my_search_svc
  ON text_column                    -- column to search over (must be VARCHAR)
  ATTRIBUTES category, region, date -- filterable metadata columns
  WAREHOUSE = compute_wh            -- warehouse for index operations
  TARGET_LAG = '1 hour'             -- index freshness target
  COMMENT = 'Product documentation search'
  AS (
    SELECT
      text_column,
      category,
      region,
      date,
      product_id
    FROM documentation_table
    WHERE is_active = TRUE
  );

Search Query Options

-- Full search with filters
SELECT PARSE_JSON(
  SNOWFLAKE.CORTEX.SEARCH(
    'my_search_svc',
    '{
      "query": "how to configure replication",
      "columns": ["text_column", "category", "product_id"],
      "filter": {"@eq": {"category": "admin-guide"}},
      "limit": 10
    }'
  )
);

Filter operators:

  • @eq - Equals
  • @contains - Contains value in array
  • @and / @or / @not - Logical operators

TARGET_LAG Behavior

  • Specifies how stale the search index can be relative to source data
  • Smaller lag = more frequent rebuilds = higher cost
  • Minimum supported: '1 minute'
  • Common values: '1 minute', '5 minutes', '1 hour', '1 day'
  • Uses the specified warehouse for refresh operations

Cortex Analyst - Deep Dive

Semantic View Structure

-- Semantic view defines business logic for Cortex Analyst
CREATE OR REPLACE SEMANTIC VIEW revenue_model
  COMMENT = 'Revenue analysis semantic model'
  -- Semantic views reference tables and define:
  -- - Entities (tables with business names)
  -- - Dimensions (categorical/descriptive columns)
  -- - Measures (numeric aggregatable columns)  
  -- - Time dimensions (date/timestamp columns)
  -- - Relationships (joins between tables)
  -- - Verified queries (known Q&A pairs for accuracy)
;

Verified Queries

Pre-defined question-SQL pairs that improve accuracy:

  • Teach Cortex Analyst the "correct" SQL for common questions
  • Act as few-shot examples during query generation
  • Reduce hallucination for frequently asked questions
  • Should cover the most important/common business questions

ML Functions (Built-in Models)

FORECAST - Time Series Prediction

-- Step 1: Create a forecast model
CREATE OR REPLACE SNOWFLAKE.ML.FORECAST my_forecast_model(
  INPUT_DATA => SYSTEM$REFERENCE('VIEW', 'sales_time_series'),
  TIMESTAMP_COLNAME => 'sale_date',
  TARGET_COLNAME => 'daily_revenue'
);

-- Step 2: Generate predictions
CALL my_forecast_model!FORECAST(
  FORECASTING_PERIODS => 30,      -- predict 30 periods ahead
  CONFIG_OBJECT => {'prediction_interval': 0.95}
);
  • Automated time series forecasting (no ML expertise needed)
  • Supports multiple series (e.g., forecast per region)
  • Returns point predictions + confidence intervals
  • Handles seasonality, trends automatically

ANOMALY_DETECTION

-- Create anomaly detection model
CREATE OR REPLACE SNOWFLAKE.ML.ANOMALY_DETECTION my_anomaly_model(
  INPUT_DATA => SYSTEM$REFERENCE('VIEW', 'server_metrics'),
  TIMESTAMP_COLNAME => 'metric_time',
  TARGET_COLNAME => 'cpu_usage',
  LABEL_COLNAME => ''  -- unsupervised (no labels)
);

-- Detect anomalies
CALL my_anomaly_model!DETECT_ANOMALIES(
  INPUT_DATA => SYSTEM$REFERENCE('VIEW', 'new_metrics'),
  TIMESTAMP_COLNAME => 'metric_time',
  TARGET_COLNAME => 'cpu_usage',
  CONFIG_OBJECT => {'prediction_interval': 0.99}
);
  • Detects outliers in time series data
  • Supports supervised (with labels) and unsupervised modes
  • Returns is_anomaly flag + anomaly score

CLASSIFICATION

-- Create classification model
CREATE OR REPLACE SNOWFLAKE.ML.CLASSIFICATION my_classifier(
  INPUT_DATA => SYSTEM$REFERENCE('VIEW', 'training_data'),
  TARGET_COLNAME => 'churn_label'
);

-- Predict on new data
SELECT my_classifier!PREDICT(
  INPUT_DATA => OBJECT_CONSTRUCT(*)
) AS prediction
FROM new_customers;
  • Binary and multi-class classification
  • Automated feature engineering
  • Returns predicted class + probability scores
  • No hyperparameter tuning needed
ML functions (FORECAST, ANOMALY_DETECTION, CLASSIFICATION) use a two-step pattern: (1) CREATE the model object, (2) CALL the model's method (FORECAST, DETECT_ANOMALIES, or PREDICT).

Cost Model

Per-Token Billing

ComponentBilling BasisNotes
LLM Functions (AI_COMPLETE)Credits per 1M tokensInput + output tokens counted separately
AI_SENTIMENT, AI_SUMMARIZE, etc.Credits per 1M tokensUses built-in models
AI_EMBED_TEXTCredits per 1M tokensBased on input text length
Cortex SearchServerless creditsIndex build + query serving
Fine-tuningCredits per training tokenOne-time training cost + inference cost
ML FunctionsServerless creditsModel training + prediction

Cost factors:

  • Model size: Larger models cost more per token
  • Input length: Longer prompts = more tokens = higher cost
  • Output length: Longer responses cost more
  • Batch size: Processing millions of rows adds up quickly
Cost Optimization Tips:
  • Use the smallest model that meets quality requirements
  • Set max_tokens to limit output length
  • Pre-filter data before applying AI functions
  • Cache results for repeated queries (store in tables)
  • Use AI_SENTIMENT/AI_SUMMARIZE (cheaper) instead of AI_COMPLETE when possible

Prompt Engineering

  • Be specific - Clear instructions produce better results
  • Use system prompts - Set persona and constraints upfront
  • Provide examples - Few-shot examples in the prompt improve consistency
  • Request format - Ask for JSON, bullet points, or specific structure
  • Set temperature appropriately - Low (0-0.3) for factual, high (0.7-1) for creative
  • Limit output - Use max_tokens to control costs and response length

Cost Management

  • Right-size models - Don't use 405B for simple sentiment analysis
  • Batch intelligently - Process in batches, store results, avoid reprocessing
  • Pre-filter data - Apply WHERE clauses before AI functions
  • Monitor usage - Use ACCOUNT_USAGE views to track Cortex consumption
  • Set resource monitors - Alert on unexpected Cortex spending
  • Cache results - Store AI outputs in tables for repeated access
