SQL Fundamentals Theory - Part 1

Window Functions, QUALIFY, CTEs, Recursive CTEs, MERGE, LATERAL Joins

1. Window Functions Overview

Window functions perform calculations across a set of rows related to the current row WITHOUT collapsing rows (unlike GROUP BY). They use the OVER() clause.

SELECT column,
       window_function() OVER (
         [PARTITION BY partition_cols]
         [ORDER BY order_cols]
         [window_frame]
       )
FROM table;

Key concept: Window functions execute AFTER WHERE, GROUP BY, and HAVING but BEFORE ORDER BY and LIMIT.

1.1 Ranking Functions

FunctionBehavior with TiesGaps?Example (vals: 10,20,20,30)
ROW_NUMBER()Assigns unique sequential numberNo gaps, no ties1, 2, 3, 4
RANK()Same rank for tiesYes, gaps after ties1, 2, 2, 4
DENSE_RANK()Same rank for tiesNo gaps1, 2, 2, 3
NTILE(n)Divides into n bucketsDistributes evenlyNTILE(2): 1,1,2,2
-- ROW_NUMBER: always unique (non-deterministic with ties unless ORDER BY is unique)
SELECT name, salary,
  ROW_NUMBER() OVER (ORDER BY salary DESC) as row_num,
  RANK()       OVER (ORDER BY salary DESC) as rnk,
  DENSE_RANK() OVER (ORDER BY salary DESC) as dense_rnk
FROM employees;

-- NTILE: divide into quartiles
SELECT name, salary,
  NTILE(4) OVER (ORDER BY salary) as quartile
FROM employees;
Exam Tip: ROW_NUMBER with ties is NON-DETERMINISTIC — the same query may return different row numbers for tied values across executions. Add a tiebreaker column to make it deterministic.

1.2 Value Functions: LEAD, LAG, FIRST_VALUE, LAST_VALUE

FunctionPurposeSyntax
LAG(col, n, default)Access previous row's valuen=offset (default 1), default if no row
LEAD(col, n, default)Access next row's valuen=offset (default 1), default if no row
FIRST_VALUE(col)First value in window frameRespects frame clause
LAST_VALUE(col)Last value in window frameDefault frame may surprise you!
-- LAG/LEAD for comparing with previous/next row
SELECT date, revenue,
  LAG(revenue, 1, 0)  OVER (ORDER BY date) as prev_revenue,
  LEAD(revenue, 1, 0) OVER (ORDER BY date) as next_revenue,
  revenue - LAG(revenue) OVER (ORDER BY date) as daily_change
FROM daily_sales;

-- FIRST_VALUE / LAST_VALUE
SELECT department, employee, salary,
  FIRST_VALUE(employee) OVER (
    PARTITION BY department ORDER BY salary DESC
  ) as highest_paid,
  LAST_VALUE(employee) OVER (
    PARTITION BY department ORDER BY salary DESC
    ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
  ) as lowest_paid
FROM employees;
Exam Tip: LAST_VALUE with the default frame (ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) gives you the CURRENT row's value, not the actual last value! Always use ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING with LAST_VALUE.

2. Window Frames: ROWS vs RANGE

window_frame ::=
  { ROWS | RANGE } BETWEEN frame_start AND frame_end

frame_start/end ::=
  UNBOUNDED PRECEDING
  | n PRECEDING
  | CURRENT ROW
  | n FOLLOWING
  | UNBOUNDED FOLLOWING
Frame TypeBehaviorUse Case
ROWSPhysical rows: exact count of rows before/afterMoving average over N rows
RANGELogical range: includes all rows with same ORDER BY valueRunning total (includes ties)
-- ROWS: exactly 2 preceding physical rows + current
SELECT date, amount,
  SUM(amount) OVER (ORDER BY date ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)
    as moving_3day_sum
FROM sales;

-- RANGE: all rows with same value (ties included)
SELECT date, amount,
  SUM(amount) OVER (ORDER BY date RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
    as running_total
FROM sales;

-- Default frame when ORDER BY is specified:
-- RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
-- Default frame when NO ORDER BY:
-- ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING (entire partition)
Exam Tip: The DEFAULT frame is RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW when ORDER BY is present. This means SUM() OVER (ORDER BY date) gives a running total, not a grand total!

3. QUALIFY Clause

QUALIFY filters the results of window functions — it is to window functions what HAVING is to GROUP BY.

-- SQL execution order: FROM → WHERE → GROUP BY → HAVING → 
--   Window Functions → QUALIFY → DISTINCT → ORDER BY → LIMIT

-- Get top 1 per department (Snowflake-specific, much cleaner than subquery)
SELECT department, employee, salary
FROM employees
QUALIFY ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) = 1;

-- Equivalent without QUALIFY (standard SQL):
SELECT * FROM (
  SELECT department, employee, salary,
    ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) as rn
  FROM employees
) WHERE rn = 1;

-- QUALIFY with RANK (get all tied top earners)
SELECT department, employee, salary
FROM employees
QUALIFY RANK() OVER (PARTITION BY department ORDER BY salary DESC) = 1;
Exam Tip: QUALIFY is a Snowflake extension (not standard SQL). It executes AFTER window functions. You can reference window functions in QUALIFY even without them in SELECT. It drastically simplifies "top-N per group" queries.

4. Common Table Expressions (CTEs)

-- Basic CTE
WITH monthly_totals AS (
  SELECT DATE_TRUNC('month', order_date) as month,
         SUM(amount) as total
  FROM orders
  GROUP BY 1
),
ranked AS (
  SELECT month, total,
    RANK() OVER (ORDER BY total DESC) as rnk
  FROM monthly_totals
)
SELECT * FROM ranked WHERE rnk <= 3;

-- Key properties:
-- 1. CTEs are evaluated once per reference (not materialized by default)
-- 2. Multiple CTEs separated by commas
-- 3. Later CTEs can reference earlier CTEs
-- 4. Column aliases in CTE are optional: WITH cte(col1, col2) AS (...)

4.1 Recursive CTEs

-- Recursive CTE structure
WITH RECURSIVE cte_name AS (
  -- Anchor member (base case): executed once
  SELECT initial_columns FROM table WHERE base_condition
  
  UNION ALL
  
  -- Recursive member: references cte_name, executed repeatedly
  SELECT derived_columns FROM table
  JOIN cte_name ON recursive_condition
)
SELECT * FROM cte_name;

-- Example: Org hierarchy
WITH RECURSIVE org_tree AS (
  -- Anchor: top-level managers (no manager)
  SELECT employee_id, name, manager_id, 1 as level,
         name::VARCHAR as path
  FROM employees
  WHERE manager_id IS NULL
  
  UNION ALL
  
  -- Recursive: find reports of current level
  SELECT e.employee_id, e.name, e.manager_id, t.level + 1,
         t.path || ' > ' || e.name
  FROM employees e
  JOIN org_tree t ON e.manager_id = t.employee_id
)
SELECT * FROM org_tree ORDER BY path;
Exam Tip: Recursive CTEs require RECURSIVE keyword in Snowflake. Default max recursion depth is 100 iterations. Use ALTER SESSION SET MAX_RECURSIONS = n; to change. UNION ALL (not UNION) is required in the recursive member.

5. MERGE Statement

MERGE performs INSERT, UPDATE, and/or DELETE in a single atomic statement (upsert pattern).

MERGE INTO target_table t
USING source_table s
ON t.id = s.id

-- When rows match (exist in both)
WHEN MATCHED AND s.status = 'DELETE' THEN DELETE
WHEN MATCHED THEN UPDATE SET
  t.name = s.name,
  t.updated_at = CURRENT_TIMESTAMP()

-- When rows exist only in source
WHEN NOT MATCHED THEN INSERT (id, name, created_at)
  VALUES (s.id, s.name, CURRENT_TIMESTAMP());

MERGE Rules and Behavior

RuleDetail
Multiple WHEN MATCHEDUp to 2 clauses allowed (with different conditions)
Multiple WHEN NOT MATCHEDUp to 1 INSERT clause allowed
Clause OrderClauses evaluated in order written; first match wins
Duplicate HandlingError if source has duplicates matching same target row (non-deterministic)
AtomicityEntire MERGE is a single transaction
Exam Tip: If source has duplicate keys matching the same target row, MERGE raises a non-deterministic error. Deduplicate your source first! Also: MERGE does NOT support WHEN NOT MATCHED BY SOURCE (unlike SQL Server).

6. LATERAL Joins

LATERAL allows a subquery in FROM to reference columns from preceding tables in the same FROM clause (correlated inline view).

-- Without LATERAL (doesn't work - can't reference o.order_id in subquery)
-- SELECT * FROM orders o, (SELECT * FROM items WHERE order_id = o.order_id);

-- With LATERAL (works!)
SELECT o.order_id, o.customer_id, i.item_name, i.amount
FROM orders o,
LATERAL (
  SELECT item_name, amount
  FROM order_items
  WHERE order_id = o.order_id
  ORDER BY amount DESC
  LIMIT 3
) i;

-- LATERAL FLATTEN (most common Snowflake use)
SELECT r.id, f.value::STRING as tag
FROM raw_data r,
LATERAL FLATTEN(input => r.tags_array) f;

-- LATERAL with table function
SELECT e.name, d.value
FROM events e,
LATERAL FLATTEN(input => PARSE_JSON(e.payload)) d;
Exam Tip: LATERAL FLATTEN is the standard pattern for expanding arrays/objects in Snowflake semi-structured data. LATERAL is required when the subquery/function references the outer table. Without LATERAL, subqueries in FROM are independent.

7. Features and Limitations Summary

15 Key Features

  1. Window functions preserve all rows (no collapsing)
  2. PARTITION BY creates independent groups within windows
  3. Multiple window functions in single SELECT
  4. QUALIFY eliminates subquery wrappers for filtering
  5. Named windows with WINDOW clause for reuse
  6. CTEs improve readability and enable self-referencing
  7. Recursive CTEs handle hierarchical/graph data
  8. MERGE combines INSERT/UPDATE/DELETE atomically
  9. LATERAL enables correlated subqueries in FROM
  10. LATERAL FLATTEN expands semi-structured data inline
  11. Window frames (ROWS/RANGE) give precise control
  12. LAG/LEAD access adjacent rows without self-join
  13. NTILE provides bucket-based distribution
  14. FIRST_VALUE/LAST_VALUE with frames for extremes
  15. QUALIFY works with aliases defined in same SELECT

15 Key Limitations

  1. ROW_NUMBER with ties is non-deterministic
  2. LAST_VALUE default frame only sees up to current row
  3. RANGE frame requires exactly one ORDER BY column
  4. Window functions cannot be nested inside other window functions
  5. Cannot use window functions in WHERE clause (use QUALIFY)
  6. Cannot use window functions in GROUP BY or HAVING
  7. Recursive CTEs max 100 iterations by default
  8. Recursive CTEs require UNION ALL (not UNION)
  9. MERGE errors on duplicate source-to-target matches
  10. MERGE: max 2 WHEN MATCHED, 1 WHEN NOT MATCHED
  11. No WHEN NOT MATCHED BY SOURCE in Snowflake MERGE
  12. QUALIFY is Snowflake-specific (not portable SQL)
  13. CTEs are not materialized by default (re-executed per reference)
  14. LATERAL subqueries execute per outer row (performance cost)
  15. Window frames with RANGE only work with numeric/date types
