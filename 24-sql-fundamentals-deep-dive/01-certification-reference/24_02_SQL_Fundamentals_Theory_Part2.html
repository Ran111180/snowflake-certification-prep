SQL Fundamentals Theory - Part 2

PIVOT/UNPIVOT, GENERATOR, Conditionals, Strings, Dates, Type Conversion, SAMPLE, GROUPING SETS, Transactions

1. PIVOT and UNPIVOT

PIVOT: Rows to Columns

-- PIVOT syntax
SELECT *
FROM monthly_sales
  PIVOT (
    SUM(amount) FOR month IN ('Jan', 'Feb', 'Mar', 'Apr')
  ) AS p (product, jan_sales, feb_sales, mar_sales, apr_sales);

-- Dynamic pivot is NOT supported natively — IN list must be static literals
-- Workaround: generate SQL dynamically with a stored procedure

UNPIVOT: Columns to Rows

-- UNPIVOT syntax
SELECT product, quarter, revenue
FROM quarterly_revenue
  UNPIVOT (
    revenue FOR quarter IN (q1_revenue, q2_revenue, q3_revenue, q4_revenue)
  );

-- Note: UNPIVOT excludes NULLs by default
-- Use: UNPIVOT INCLUDE NULLS (...) to keep NULL values
Exam Tip: PIVOT IN list must contain literal values (not subqueries). UNPIVOT removes NULLs by default — add INCLUDE NULLS if needed. The aggregate in PIVOT must be a single aggregate function.

2. GENERATOR and SEQUENCE

GENERATOR: Create Rows from Nothing

-- Generate exactly 10 rows
SELECT SEQ4() as row_num
FROM TABLE(GENERATOR(ROWCOUNT => 10));

-- Generate date series (last 30 days)
SELECT DATEADD('day', -SEQ4(), CURRENT_DATE()) as date_val
FROM TABLE(GENERATOR(ROWCOUNT => 30))
ORDER BY date_val;

-- Generate with time limit (rows generated in N seconds)
SELECT SEQ4() FROM TABLE(GENERATOR(TIMELIMIT => 1));

-- Combine GENERATOR with ROW_NUMBER
SELECT ROW_NUMBER() OVER (ORDER BY SEQ4()) - 1 as n
FROM TABLE(GENERATOR(ROWCOUNT => 100));

SEQUENCE: Auto-incrementing Values

-- Create sequence
CREATE OR REPLACE SEQUENCE my_seq
  START = 1
  INCREMENT = 1;

-- Use in INSERT
INSERT INTO my_table (id, name)
SELECT my_seq.NEXTVAL, 'Product_' || SEQ4()::VARCHAR
FROM TABLE(GENERATOR(ROWCOUNT => 5));

-- Sequences are NOT gap-free (gaps on rollback, multi-node)
-- Sequences guarantee uniqueness, not contiguity
Exam Tip: GENERATOR + SEQ4()/SEQ8() is the Snowflake pattern for generating test data. SEQ4() returns 0-based sequence per query. Sequences guarantee uniqueness but NOT contiguity (gaps are normal).

-- IFF: ternary operator
SELECT IFF(salary > 100000, 'High', 'Standard') as band FROM employees;

-- CASE: searched vs simple
SELECT CASE
  WHEN score >= 90 THEN 'A'
  WHEN score >= 80 THEN 'B'
  ELSE 'C'
END as grade;

SELECT CASE department   -- simple CASE
  WHEN 'ENG' THEN 'Engineering'
  WHEN 'MKT' THEN 'Marketing'
  ELSE 'Other'
END;

-- DECODE: NULL-safe equality comparison
SELECT DECODE(status, 'A', 'Active', 'I', 'Inactive', 'Unknown');
-- DECODE treats NULL = NULL as TRUE (unlike normal comparison!)

-- COALESCE vs NVL
SELECT COALESCE(phone, mobile, email, 'No Contact') as contact;
SELECT NVL(phone, 'No Phone');  -- only 2 arguments
Exam Tip: DECODE considers NULL = NULL as TRUE (unlike = operator). NVL evaluates both arguments always; COALESCE short-circuits. NULLIF is useful to convert empty strings or zero to NULL before aggregation.

4. String Functions

-- SPLIT_PART: extract part of delimited string
SELECT SPLIT_PART('a.b.c.d', '.', 2);  -- Returns 'b'
SELECT SPLIT_PART('a.b.c.d', '.', -1); -- Returns 'd' (from end)

-- SPLIT_TO_TABLE: one row per token
SELECT t.value
FROM TABLE(SPLIT_TO_TABLE('a,b,c', ',')) t;

-- REGEXP functions
SELECT REGEXP_LIKE('Hello123', '[A-Za-z]+[0-9]+');  -- TRUE
SELECT REGEXP_SUBSTR('Price: $45.99', '\\$[0-9.]+'); -- '$45.99'
SELECT REGEXP_REPLACE('Hello   World', '\\s+', ' '); -- 'Hello World'
SELECT REGEXP_COUNT('aaa bbb aaa', 'aaa');           -- 2
SELECT REGEXP_INSTR('abc 123 def', '[0-9]+');        -- 5

-- Other useful string functions
SELECT INITCAP('hello world');          -- 'Hello World'
SELECT REPEAT('ab', 3);                 -- 'ababab'
SELECT LPAD('42', 5, '0');              -- '00042'
SELECT TRIM('  hello  ');               -- 'hello'
SELECT POSITION('world' IN 'hello world'); -- 7
SELECT REPLACE('foo-bar-baz', '-', '_'); -- 'foo_bar_baz'
SELECT CONCAT_WS('-', '2024', '01', '15'); -- '2024-01-15'
Exam Tip: SPLIT_PART uses 1-based indexing. Negative index counts from the end. REGEXP in Snowflake uses backslash escaping in single-quoted strings (double backslash: '\\d+'). Use $$ delimiters to avoid: $$\d+$$.

5. Date and Time Functions

-- DATEDIFF: difference between two dates
SELECT DATEDIFF('day', '2024-01-01', '2024-03-15');     -- 74
SELECT DATEDIFF('month', '2024-01-15', '2024-03-01');   -- 2
SELECT DATEDIFF('year', '2023-12-31', '2024-01-01');    -- 1 (crosses year boundary)

-- DATEADD: add interval to date
SELECT DATEADD('month', 3, '2024-01-31');  -- 2024-04-30 (end-of-month adjusted)
SELECT DATEADD('day', -7, CURRENT_DATE()); -- 7 days ago

-- DATE_TRUNC: truncate to specified precision
SELECT DATE_TRUNC('month', '2024-03-15'::DATE);  -- 2024-03-01
SELECT DATE_TRUNC('week', '2024-03-15'::DATE);   -- 2024-03-11 (Monday)
SELECT DATE_TRUNC('quarter', CURRENT_TIMESTAMP());

-- EXTRACT / DATE_PART
SELECT EXTRACT(year FROM '2024-03-15'::DATE);      -- 2024
SELECT DATE_PART('dow', '2024-03-15'::DATE);       -- 5 (0=Sunday)
SELECT DAYNAME('2024-03-15'::DATE);                -- 'Fri'
SELECT LAST_DAY('2024-02-15'::DATE);               -- 2024-02-29
SELECT LAST_DAY('2024-02-15'::DATE, 'month');      -- 2024-02-29

-- Timestamp functions
SELECT CURRENT_TIMESTAMP();          -- session timezone
SELECT CONVERT_TIMEZONE('UTC', 'America/New_York', CURRENT_TIMESTAMP());
SELECT TO_TIMESTAMP('2024-03-15 10:30:00', 'YYYY-MM-DD HH24:MI:SS');
Exam Tip: DATEDIFF counts boundaries crossed, not complete units. DATEDIFF('year', '2023-12-31', '2024-01-01') = 1 even though it's only 1 day apart! DATE_TRUNC('week',...) uses Monday as week start by default (ISO).

6. Type Conversion

-- :: operator (Snowflake shorthand for CAST)
SELECT '42'::INTEGER;           -- 42
SELECT '2024-01-15'::DATE;      -- 2024-01-15
SELECT 3.14159::DECIMAL(5,2);   -- 3.14

-- CAST function (standard SQL)
SELECT CAST('42' AS INTEGER);
SELECT CAST(price AS DECIMAL(10,2));

-- TRY_CAST: returns NULL on failure instead of error
SELECT TRY_CAST('abc' AS INTEGER);    -- NULL (no error!)
SELECT TRY_CAST('42' AS INTEGER);     -- 42
SELECT CAST('abc' AS INTEGER);        -- ERROR!

-- TRY_ variants for safe conversion
SELECT TRY_TO_NUMBER('$42.50', '$99.99');  -- 42.50
SELECT TRY_TO_DATE('not-a-date');          -- NULL
SELECT TRY_TO_TIMESTAMP('invalid');        -- NULL

-- TO_ conversion functions
SELECT TO_VARCHAR(CURRENT_DATE(), 'YYYY-MM-DD');
SELECT TO_NUMBER('42.5', '99.9');
SELECT TO_DATE('15/03/2024', 'DD/MM/YYYY');
SELECT TO_CHAR(12345.67, '$999,999.99');   -- '$12,345.67'
Exam Tip: TRY_CAST and TRY_TO_* functions are critical for handling dirty data — they return NULL instead of raising errors. The :: operator is Snowflake shorthand identical to CAST. Integer division truncates: 5/2 = 2 not 2.5!

7. SAMPLE / TABLESAMPLE

-- Row-based sampling (percentage)
SELECT * FROM large_table SAMPLE (10);       -- ~10% of rows
SELECT * FROM large_table TABLESAMPLE (10);  -- same thing

-- Fixed row count
SELECT * FROM large_table SAMPLE (100 ROWS); -- exactly 100 rows

-- Block-based sampling (faster for large tables, less uniform)
SELECT * FROM large_table SAMPLE BLOCK (10); -- ~10% of micro-partitions

-- Seed for reproducibility
SELECT * FROM large_table SAMPLE (10) SEED(42);
SELECT * FROM large_table SAMPLE (10) REPEATABLE(42); -- same as SEED

-- Bernoulli (row) vs System (block)
SELECT * FROM t SAMPLE BERNOULLI (10);  -- row-level, uniform
SELECT * FROM t SAMPLE SYSTEM (10);     -- block-level, faster
Exam Tip: SAMPLE(n) without ROWS keyword means n percent. With ROWS keyword means exact count. BERNOULLI = row-level sampling (uniform). SYSTEM = block/micro-partition level (faster but less uniform). SEED makes sampling reproducible.

8. GROUPING SETS, CUBE, ROLLUP

-- GROUPING SETS: specify exact grouping combinations
SELECT region, product, SUM(sales) as total_sales
FROM sales_data
GROUP BY GROUPING SETS (
  (region, product),  -- group by both
  (region),           -- subtotal by region
  (product),          -- subtotal by product
  ()                  -- grand total
);

-- ROLLUP: hierarchical subtotals (n+1 grouping sets)
SELECT region, city, SUM(sales)
FROM sales_data
GROUP BY ROLLUP (region, city);
-- Equivalent to: GROUPING SETS ((region, city), (region), ())

-- CUBE: all possible combinations (2^n grouping sets)
SELECT region, product, SUM(sales)
FROM sales_data
GROUP BY CUBE (region, product);
-- Equivalent to: GROUPING SETS ((region, product), (region), (product), ())

-- GROUPING() function: identifies subtotal rows (0=real, 1=subtotal)
SELECT 
  region, product, SUM(sales),
  GROUPING(region) as is_region_subtotal,
  GROUPING(product) as is_product_subtotal
FROM sales_data
GROUP BY CUBE (region, product);
Exam Tip: ROLLUP(a, b, c) produces 4 grouping sets: (a,b,c), (a,b), (a), (). CUBE(a, b, c) produces 8 (2^3). Use GROUPING() to distinguish NULLs from data vs NULLs from subtotals. GROUPING returns 1 for subtotal rows.

9. Transactions

-- Explicit transaction
BEGIN TRANSACTION;
  INSERT INTO orders VALUES (1, 'Widget', 100);
  INSERT INTO audit_log VALUES (1, CURRENT_TIMESTAMP(), 'INSERT');
COMMIT;

-- Rollback on error
BEGIN;
  UPDATE accounts SET balance = balance - 500 WHERE id = 1;
  UPDATE accounts SET balance = balance + 500 WHERE id = 2;
  -- If any statement fails, rollback everything:
ROLLBACK;  -- or COMMIT if successful

-- Auto-commit behavior (default)
-- Each DML statement is its own transaction unless BEGIN is used
-- DDL statements auto-commit (cannot be rolled back)

-- Scoped transactions in stored procedures
CREATE PROCEDURE transfer(from_id INT, to_id INT, amount NUMBER)
RETURNS VARCHAR
LANGUAGE SQL
AS
BEGIN
  BEGIN TRANSACTION;
    UPDATE accounts SET balance = balance - amount WHERE id = :from_id;
    UPDATE accounts SET balance = balance + amount WHERE id = :to_id;
  COMMIT;
  RETURN 'Success';
EXCEPTION
  WHEN OTHER THEN
    ROLLBACK;
    RETURN 'Failed: ' || SQLERRM;
END;

Transaction Rules in Snowflake

PropertyBehavior
Default isolationREAD COMMITTED
DDL in transactionAuto-commits (breaks transaction)
TimeoutDefault 4 hours (STATEMENT_TIMEOUT_IN_SECONDS)
Lock scopeTable-level for DML (partition-level internally)
Nested transactionsNot supported (BEGIN inside BEGIN has no effect)
AUTOCOMMITDefault ON — each statement auto-commits if no explicit BEGIN
Exam Tip: DDL statements (CREATE, DROP, ALTER) cannot be rolled back — they auto-commit. Snowflake does NOT support nested transactions or savepoints. Isolation level is always READ COMMITTED (no SERIALIZABLE option for tables).
